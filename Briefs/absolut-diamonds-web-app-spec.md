# אפיון — אפליקציית ווב לתכשיטים (Absolut Diamonds / AB Atelier)

> **מקור:** פגישה חיה עם שלומי ומיכאל (השותפים), 2026-08-13, בתיווך רונן.
> **תויק ע"י דורית:** 2026-08-13
> **הקשר:** פיבוט שני. מסלול קודם: [[ab-atelier-spec-review|אפיון חנות Shopify]] → דף נחיתה ([[ab-atelier-landing-page]]) → **עכשיו: אפליקציית ווב (קטלוג צד-לקוח)**.
> **דף הנחיתה יורד מהשולחן** — האפליקציה מחליפה אותו. הסיבה שהלקוח נתן: דף נחיתה מציג מוצר אחד, והם צריכים להציג **מגוון** טבעות/שרשראות/עגילים/צמידים.

## 1. מטרה

אפליקציית ווב **צד-לקוח** שמציגה קטלוג תכשיטים אמיתי עם מפרט יהלום מלא ומחיר, ומובילה לפנייה (וואטסאפ / טופס). המטרה: לתת ללקוח לחפש, לסנן ולהשוות פריטים — ואז לדבר עם שלומי/מיכאל.

**מבחן ההצדקה (למה אפליקציה ולא דף נחיתה):** מגוון פריטים + סינון לפי מפרט יהלום + מלאי שמתחלף עונתית. דף סטטי לא נותן את זה.

## 2. משתמשים והרשאות

| משתמש | כניסה | מה עושה |
|---|---|---|
| **לקוח** (מבקר) | **ללא הרשמה, ללא התחברות** — כל אחד נכנס | גולש בקטלוג, מסנן, צופה בפריט, פונה בוואטסאפ / משאיר פרטים |
| **אדמין** (רונן / שלומי / מיכאל) | התחברות מוגנת | מוסיף/עורך/מסתיר פריטים, מעלה תמונות, מעדכן מחירים, רואה לידים |

> **החלטה:** אין חשבונות לקוח בפרוסה 1 (החלטת הלקוח). מסך ניהול **כן** נדרש — כי הצוות מעדכן את המלאי עונתית ואי אפשר שכל שינוי יהיה שינוי קוד.

## 3. מודל הנתונים

> **עודכן 2026-08-13 לפי תשובת הלקוח:** המוצר הוא **קונפיגורטור**, לא קטלוג פריטים מוגמרים.
> הלקוח בוחר **דגם** → מחליף **צבע מתכת** → מחליף **יהלום**. המחיר **מחושב**.
> לכן שתי ישויות מלאי נפרדות — דגמים ואבנים — ולא ישות `products` אחת.

### `models` — דגם תכשיט (השיבוץ, בלי האבן)
- זהות: `sku`, `category`, `subcategory`, `title_he/en`, `description_he/en`
- קטגוריות: **טבעות** (אירוסין / נישואין), **עגילים**, **שרשראות**, **צמידים** — ✅ אושר ע"י הלקוח
- מחיר: `basePrice` — מחיר הדגם **בלי אבן**
- מתכת: `metalOptions[]` (צהוב / לבן / ורוד), `metalKarat` (14k/18k)
- תמונות: **`imagesByMetal: { yellow[], white[], rose[] }`** — סט תמונות לכל צבע מתכת. זה מסביר את ~100 התמונות הנרכשות.
- תאימות: `compatibleShapes[]`, `caratRange` (min/max) — לא כל אבן נכנסת לכל שיבוץ
- ניהול: `status`, `featured`, `sortOrder`, `collection`/`season`

### `diamonds` — מלאי אבנים
- `stoneId`, `carat`, `shape` (עגול/פרינסס/אובל/מרקיזה/אגס/אמרלד/קושן/הארט/רדיאנט/אשר)
- `color` (D–Z), `clarity` (FL…I3), `cut`, **`origin` — טבעי / מעבדה (חובה, מסונן, חובת גילוי)**
- תעודה: `certLab` = **IGI**, `certNumber`, `certFileUrl`
- `price`, `currency` = ILS, `status` (זמין / נמכר / מוסתר)
- `images[]`, **`imageIsIllustrative`** (דגל — ראה סיכון 7.1)

### `leads` — פנייה
`name`, `phone`, `email?`, `message?`, `source`, `createdAt`, `consentAt`
\+ **הקונפיגורציה שהורכבה:** `modelId`, `metalColor`, `metalKarat`, `diamondId`, `computedPrice`
> זה כל הערך של הליד — בלעדיו שלומי מקבל "מישהו התעניין" במקום "מישהו הרכיב טבעת ב-₪18,400".
> PII — גם בלי הרשמה, ועכשיו גם מידע מסחרי. נכנס לשער עדי.

### חישוב מחיר
`basePrice` (לפי מתכת/קראט) + `diamond.price` = סה"כ. **פירוק שקוף** — שיבוץ / אבן / סה"כ.

### `settings` — תוכן שהצוות עורך
מספר וואטסאפ, מייל, לינקים לרשתות, טקסט hero, סיפור מותג, FAQ.

## 4. מסכים (פרוסה 1)

1. **בית** — hero, 4 קטגוריות, דגמים נבחרים, סיפור מותג קצר, FAQ, יצירת קשר
2. **קטלוג דגמים** — גריד של **דגמים** (לא אבנים), מחיר מוצג כ**"החל מ-₪X"**. סינון: קטגוריה, מתכת, טווח מחיר.
3. **דף דגם + קונפיגורטור** ← **המסך המרכזי של האפליקציה**
   - התכשיט מתחלף מיידית לפי **צבע המתכת** שנבחר
   - **בחירת יהלום** מתוך המלאי, מסונן אוטומטית לפי `compatibleShapes` + `caratRange` של הדגם
   - סינון אבנים: צורה, טווח קראט, צבע, ניקיון, **טבעי/מעבדה**, טווח מחיר
   - טבלת 4C + תעודת IGI לאבן שנבחרה; **המחיר מתעדכן חי** עם פירוק שקוף
   - **CTA כפול:** וואטסאפ עם הודעה מוכנה הכוללת את **הקונפיגורציה המלאה** (דגם + מתכת + מפרט אבן + מס' IGI + מחיר), + טופס פנייה שמצרף אותה
4. **צור קשר** — טופס ליד + וואטסאפ צף
5. **אודות / FAQ** — סיפור המותג, שאלות על יהלומים (טבעי מול מעבדה, איך בוחרים)
6. **ניהול (מוגן בסיסמה)** — ✅ אושר ע"י הלקוח. **שני מנהלי מלאי נפרדים:** דגמים (עם תמונות פר-מתכת) ואבנים (המתעדכן ביותר — טבלה + עריכה מהירה). + ניהול לידים + עריכת `settings`

## 5. דרישות רוחב

- **שפה:** עברית ברירת מחדל + אנגלית. RTL/LTR מלא.
- **מובייל-first** — רוב התנועה תגיע מאינסטגרם/וואטסאפ.
- **נגישות** — ת"י 5568 / WCAG AA.
- **ביצועים** — תמונות תכשיטים כבדות; חובה lazy-load + גדלים רספונסיביים.
- **מיתוג:** **placeholder בלבד.** השם "Absolut" לא נעול (ראה 7.4).

## 7. סיכונים וחוסמים

### 7.1 🔴 תמונות — מפוצל לשניים אחרי מעבר לקונפיגורטור
- **תמונת דגם** — 🟢 מוגנת יחסית. מוכרים דגם שמיוצר לפי הזמנה, לא פריט יחיד. תמונת סטוק/רנדר לגיטימית, ככל הנראה בכפוף להצהרה שהתכשיט מיוצר לפי הזמנה ושגימור/גוון עשויים להשתנות.
- **תמונת אבן ספציפית** — 🔴 הסיכון נשאר חד. אבן עם 4C + מס' תעודת IGI + מחיר, מוצגת עם תמונת סטוק, משתמעת כתמונת האבן עצמה → פרסום מטעה.
**הכלל:** סטוק ✅ לרקע, אווירה, כרטיסי קטגוריה ו**דגמים**. **אבן** ספציפית → תמונה אמיתית או סימון ברור (`imageIsIllustrative`).
⏳ עדי מפיקה ניסוח מדויק — כולל התשובה לשאלת המשתמש "האם disclaimer 'להמחשה בלבד' מרפא את זה".

### 7.2 ✅ נסגר — ללא סליקה בפרוסה 1
הלקוח אישר: **בלי סליקה.** המרה = וואטסאפ / טופס ליד בלבד. סליקה = פרוסה 2 (תדרוש ספק ישראלי — משולם / Grow / PayPlus / Tranzila — + תקנון + מדיניות החזרות).

### 7.3 ✅ נסגר — קונפיגורטור
הלקוח אישר: בוחר דגם → משנה צבע מתכת → משנה יהלום. ראה מודל הנתונים המעודכן בסעיף 3.
**סיכון נגזר חדש 🟠:** מחיר "החל מ-₪X" בגלריית הדגמים — כפוף לכללי הצגת מחירים לצרכן; ובנוסף, הקונפיגורציה השמורה בליד היא בפועל **הצעת מחיר** → ככל הנראה נדרש disclaimer שהמחיר אינו מחייב עד אישור וזמינות האבן. ⏳ בבדיקת עדי.

### 7.4 🟠 שם המותג לא נעול
סקירת עדי 2026-07-26: "Absolut" ← חשש דילול מול Absolut Vodka (סימן מוכר-היטב, סעיף 46א). **מותר לבנות עם placeholder — אסור להשיק תחת השם** עד clearance ברשם (סוג 14) + חוות דעת עו"ד. חלופות משירה: Keter / Tohar / AB Atelier.

### 7.5 🔴 שער עדי (חוסם deploy)
לידים = PII (שם + טלפון) גם בלי הרשמה → מדיניות פרטיות, בסיס חוקי, הסכמה. נוסף: נגישות ת"י 5568, רישוי תמונות הסטוק שנרכשות, הצגת מחירים, טענות על תעודות IGI.

### 7.6 🟡 פרטים תפעוליים חסרים
- **מספר וואטסאפ עסקי** — יועבר בהמשך. נבנה עם placeholder הניתן לעריכה ממסך הניהול.
- **כתובת מייל** — ⚠️ **תלויה בשם המותג שייבחר.** כלומר סטטוס השם (7.4) חוסם גם החלטה תפעולית, לא רק משפטית.
- **דומיין** — טרם נרכש; הלקוח ירכוש. ⚠️ **המלצה: לא לרכוש תחת "Absolut" לפני clearance** — אחרת כסף וזמן על הרצפה אם השם יוחלף.
- לינקים לרשתות — טרם התקבלו.

## 8. ארכיטקטורה

Vite + React (JavaScript) + Firebase — Firestore לקטלוג ולידים, Storage לתמונות, Auth **לאדמין בלבד** (קריאת קטלוג פומבית, כתיבה סגורה). fallback מקומי ל-localStorage כשאין קונפיג. `firestore.rules` עם deny-by-default לכל מה שאינו קריאת קטלוג.
`firebase deploy` חסום ל-Claude → רונן מריץ ידנית אחרי אישור עדי.
