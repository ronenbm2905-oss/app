# אפיון — אפליקציית ניהול נכסים (Property Management)

> מקור: `property_app_spec.docx` (רונן, אוגוסט 2026, גרסה 1). חולץ ותויק ע"י דורית.
> מסלול: **אפליקציה מלאה → נועם** (Vite + React + Firebase). לא דף נחיתה.
> שער חוסם: **עדי (Legal & Compliance)** לפני כל deploy — חשיפת פרטיות גבוהה (PII דיירים, רב-מדינה/GDPR).

## רקע ומטרה
אפליקציה לניהול נכסים לבעלי דירות בהיקף של נכס בודד עד 100 דירות. שלושה סוגי משתמשים:
**בעל הנכסים**, **דיירים** (פורטל ייעודי), **צוות ניהול/תחזוקה** (אפליקציית מובייל). המערכת שואפת
לחסוך עבודה (אוטומציה), לא רק לתעד.

## עקרונות מנחים
- היררכיית נתונים: נכס → יחידה (אופ') → דייר → חוזה → הוצאות/הכנסות → משימות → מסמכים
- MVP ממוקד (עד 6 פיצ'רים) — בלי עומס יתר
- אוטומציה כתנאי לאימוץ
- היררכיה ברורה במסך ("איפה אני ומה עליי לעשות עכשיו")
- רב-לאומי מהיסוד: מטבע + מדינה **ברמת הנכס** (ישראל, קפריסין, ארה"ב, גאורגיה…)
- סכימה גמישה מראש: מקור עדכון (ידני מול בנק עתידי), מגבלות פר-תוכנית (תמחור עתידי)
- לוקליזציה: עברית + אנגלית מה-MVP → RTL/LTR, פורמט תאריך/מטבע לפי locale, טקסטים key-based

## 1. סכימת הנתונים

### 1.1 נכס (Property)
מזהה (אוטו'), כתובת (מדינה/עיר/רחוב/מספר/דירה/קומה), **מדינה + מטבע (שדות נפרדים ברמת הנכס)**,
סוג נכס (דירה בבית משותף / מסחרי / מחסן / חניה / בית / מגרש), סטטוס (מושכר / פנוי / מוגן / פלוש /
בשיפוץ / בשותפות / הרוס / נמכר), שטח, מספר חדרים, הצמדות (חניה/גינה/גג/מחסן — רב-בחירה),
גוש/חלקה, שמירה תכנונית (בעיקר מגרשים), תמונות נכס, Airbnb/טווח-קצר (כן/לא),
פרטים כלכליים (מועד+מחיר רכישה, הון עצמי, מימון: סכום/מלווה/החזר חודשי/יתרה; עלויות נוספות:
מס רכישה/נוטריון/רישום; שיפוץ; תיווך/עו"ד), **תשואה (שדה מחושב — לא מוזן ידנית)**.

### 1.2 יחידה (Unit) — אופציונלי
לבניין/כמה יחידות תחת נכס אחד. אותם שדות בסיס, מקושר לנכס אב.

### 1.3 דייר (Tenant)
שם מלא, ת.ז., טלפון (קישור ישיר לוואטסאפ), אימייל, מועד כניסה, גורם מנהל (קיים? + פרטיו).

### 1.4 חוזה (Lease)
נכס+דייר מקושרים, תאריך התחלה/סיום, גובה שכ"ד + מועד תשלום חודשי, פיקדון (סכום+סוג),
ערבויות (מס' ערבים + סריקה), אופן תשלום, תשלומים נלווים (מים/ארנונה/חשמל/גז/ועד — כלול או לא),
קובץ חוזה סרוק, אופציית הארכה, סטטוס (פעיל / הסתיים / בחידוש).

### 1.5 תנועה כלכלית (Transaction)
נכס מקושר, סוג (הכנסה/הוצאה), קטגוריה (שכ"ד/ועד/ביטוח/מיסים/תחזוקה/מימון), סכום, תאריך,
**מקור עדכון (ידני / בנק Open Banking — שדה מוכן מהיום ל-v2)**, קובץ קבלה/חשבונית.

### 1.6 חוב (Debt)
תת-סוג של תנועה עם מעקב סטטוס: דייר/נכס מקושר, סכום, מתאריך/ימי פיגור, נשלח מכתב התראה (כן/לא),
הועבר לעו"ד (כן/לא), הסתיים (כן/לא).

### 1.7 תקלה (MaintenanceTicket)
נכס מקושר, תאריך פתיחה, סוג תקלה, תיאור, גורם מטפל (+פרטי קשר), עלות, קבלה, אחריות (כן/לא),
ביטוח (הופעל כן/לא + השתתפות עצמית), סטטוס (פתוח / בטיפול / סגור).

### 1.8 מסמך (Document)
מקושר לנכס/דייר/חוזה. סוג (חוזה שכירות/מכר, ביטוח, קבלה, ת.ז., תקנון בית משותף, ארנונה, חשמל, מים),
קובץ, תאריך העלאה, **תיוג אוטומטי ב-AI** (MVP: מסמכים סטרוקטורים — חוזה מכר/שכירות, ארנונה, חשמל, מים).

### 1.9 תזכורת / אוטומציה (Reminder)
סוג (חידוש חוזה/ביטוח/דיווח מס/בדיקה שנתית), נכס/חוזה מקושר, תאריך יעד, ימי התראה מראש (למשל 30), סטטוס.

**קשרי ישויות:** Property ← [Unit] ← Lease ← Tenant | Property → Transaction/Debt |
Property → MaintenanceTicket | Property/Tenant/Lease → Document | Property/Lease → Reminder

## 2. מסכים
- **מסך 0 — Onboarding:** זרימה מונחית (לא טופס ארוך). "כמה נכסים יש לך?" (1 / 2-5 / 6-20 / 20+) מכוונן עומק ממשק. הוספת נכס ראשון בשלבים: כתובת+סוג בלבד → הצעה לסרוק חוזה → טופס מקוצר. אף פעם לא לדרוש שדה שאינו חובה כרגע.
- **מסך 1 — לובי / רשימת נכסים:** טבלה (כתובת | סוג | שוכר | שכ"ד | מועד תשלום | סיום חוזה | חובות | תקלות פתוחות | תשואה). שורת סיכום (סה"כ הכנסות / תשואה ממוצעת / חוב פתוח). הדגשה אוטומטית: חוזה שמסתיים תוך 30 יום, חוב פתוח. לחיצה על שורה → דף נכס; על שם דייר → טלפון/וואטסאפ. כפתורים: "+ הוספת נכס", "יצירת מסמך".
- **מסך 2 — דשבורד כלכלי:** מספר נכסים, תזרים חודשי נטו, תשואה שנתית ממוצעת נטו, % נכסים בתשואה נמוכה (סף ברירת-מחדל <3%), גרף הכנסות/הוצאות לאורך זמן, רשימת מצבים קריטיים.
- **מסך 3 — דשבורד תקלות:** מסך-רוחב, כל התקלות הפתוחות (נכס | פתיחה | סוג | מטפל | ימים פתוח | עלות משוערת), מיון ברירת-מחדל זמן פתיחה יורד.
- **מסך 4 — דף נכס (טאבים):** כותרת קבועה (כתובת+סוג+סטטוס+תמונה). טאבים: כללי / דייר וחוזה / כלכלה / תקלות / מסמכים.
- **מסך 5 — פתיחת/עריכת תקלה:** סוג → תיאור → גורם מטפל → סטטוס → הצעת מחיר → עלות סופית → קבלה → ביטוח.
- **מסך 6 — פורטל דייר:** הרשאות נפרדות; דייר רואה רק את דירתו (חוזה, יתרת תשלומים, "דווח תקלה", ארכיון מסמכים).
- **מסך 7 — אפליקציית צוות תחזוקה (מובייל):** קריאות משויכות, עדכון סטטוס, העלאת תמונה/קבלה מהשטח.

## 3. MVP מול Roadmap
**ב-MVP (v1):** Onboarding (זרימה + סריקת חוזה AI בסיסי) · לובי+דשבורד · מעקב כלכלי ידני + גרפים +
חישוב תשואה · דיירים/חוזים + תזכורת חידוש · תקלות (פתיחה/שיוך/סטטוס) · מסמכים (העלאה + AI לזיהוי
חוזה מכר/שכירות/ארנונה/חשמל/מים) · תזכורות (ביטוח/חוזה/מס/בדיקות).
**לא ב-MVP (v2+):** Open Banking + קטגוריזציה אוטומטית · AI Assistant יזום · חיזוי תשואה · Marketplace
בעלי מקצוע · הפקת דוחות מס אוטומטית · הפקת חוזה אוטומטית.

## 4. החלטות פתוחות (מהמסמך)
1. רישום חברה/מיקום משפטי — נבחן (קפריסין/ארה"ב/גאורגיה). **פתרון מוצרי: מדינה+מטבע פר-נכס.**
2. ייעוץ משפטי — לוודא התמחות בפרטיות/רגולציית טכנולוגיה (רב-לאומי: ישראל, GDPR, ארה"ב). → **שער עדי.**
3. היקף AI למסמכים ב-MVP — סוכם: מסמכים סטרוקטורים (סכום/תאריך/כתובת/שם).
4. מודל תמחור — טרם הוכרע, **לא חוסם**; סכימה תתמוך במגבלות פר-תוכנית (מקס' נכסים לחשבון).
5. שפה/לוקליזציה — עברית+אנגלית מה-MVP (RTL/LTR, locale, key-based).

## החלטת דורית — סקופ פרוסה 1 ("עוגן מורחב", בחירת המשתמש 2026-08-03)

בונים בפרוסות. **פרוסה 1 = צד הבעלים, הזנה ידנית:**
- מודל נתונים **מלא** (כל הישויות מסעיף 1) — כדי לא לשבור סכימה בהמשך.
- מסך 0 (Onboarding) · מסך 1 (לובי) · מסך 4 (דף נכס עם טאבים) · מסך 2 (דשבורד כלכלי) · מסך 3 (דשבורד תקלות) · מסך 5 (פתיחת/עריכת תקלה).
- i18n עברית/אנגלית + RTL/LTR מהיום הראשון · מדינה+מטבע פר-נכס · תשואה כשדה מחושב.
- fallback מקומי (localStorage) שמתחלף ל-Firestore כשיש config.

**לא בפרוסה 1:** פורטל דייר (מסך 6) · אפליקציית תחזוקה (מסך 7) · סריקת מסמכים AI · Open Banking · תזכורות אוטומטיות (מבנה הנתונים כן מוכן, בלי מנוע התראות).

**פרוסות הבאות:** (2) פורטל דייר + אפליקציית תחזוקה · (3) סריקת מסמכים AI (Claude) + מנוע תזכורות · (4) Open Banking + AI Assistant.

**שער עדי:** סבב privacy-by-design על מודל הנתונים + firestore.rules רץ במקביל לפרוסה 1; **חסימה לפני כל deploy** — מדיניות פרטיות רב-לאומית (ישראל/GDPR/US), הסכמה, מזעור נתונים, אבטחת PII דיירים ומסמכים.
