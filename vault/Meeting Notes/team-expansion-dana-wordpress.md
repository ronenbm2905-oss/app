# הרחבת צוות: דנה — מומחית הוורדפרס

## Overview

הוספת הדמות העשירית לצוות: **דנה**, מומחית הוורדפרס. משלימה חור אמיתי — עומר בונה
HTML/CSS/JS סטטי בלי build, נועם בונה Vite+React+Firebase, ולאף אחד מהם אין PHP,
themes, plugins, Block Editor או **אתר חי שכבר רץ**. שלושה תחומי אחריות: (1) בניית
אתרי WordPress חדשים, (2) תחזוקה וניהול אתרים קיימים, (3) תוכן ו-SEO לאתר קיים.

**ההבדל המהותי שלה משאר הצוות:** אצל כולם התוצר נולד ריק ב-`Output/` ונמסר. אצל
דנה, לעיתים קרובות **כבר יש אתר** — עם תוכן, תעבורה ודירוגים שאפשר לשבור. לכן
השאלה הראשונה שלה אינה "מה לבנות" אלא **"מה אסור לשבור"**.

**מודל התפקיד** — במקביל ל"מכינה — לא שולחת" של מאיה, "מכין — לא מפרסם" של טל,
ו-deploy הידני של נועם: דנה **קוראת חי — כותבת רק באישור**. קריאה מאתר חי (REST
API `GET`, `wp` קריאה-בלבד, בדיקת ביצועים) חופשית ואף חובה לפני כל הצעה; **כל**
כתיבה לפרודקשן עוצרת לאישור מפורש של המשתמש, ומוגשת עם הפעולה המדויקת, הגיבוי
הקיים, ודרך החזרה אחורה.

## Open Questions

- **WooCommerce נשאר מחוץ לסקופ** (הכרעת רונן) — אם תגיע בקשת חנות, צריך להחליט אם
  להרחיב את דנה או להקים תפקיד eCommerce נפרד. תחום כבד בפני עצמו (סליקה ישראלית,
  מיסים, משלוחים).
- **אין עדיין אתר WordPress אמיתי בפרויקט** — דנה הוקמה לפני שיש לה תיק. הקונבנציות
  (מבנה `Output/<slug>/`, פורמט דוח האבחון) ייבחנו רק בתיק הראשון בפועל.
- **מנגנון האישור לכתיבה לפרודקשן טרם נבחן** — לא ידוע איך auto-mode יסווג בפועל
  `POST` ל-REST API של אתר חי. סביר שייחסם כמו `firebase deploy`, וזה מתיישב עם
  חוק הברזל; לוודא בתיק הראשון.
- **סוד ראשון שייכנס לפרויקט** — עד היום `.env` החזיק רק מפתחות Firebase Web
  (ציבוריים בהגדרה). Application Password של WP הוא הסוד האמיתי הראשון, וריפו
  הצוות **ציבורי** ([[git-repo-topology]]). כדאי לשקול בדיקת סודות לפני קומיט.
- שני התפקידים שהומלצו ב-[[team-expansion-noam-fullstack]] — **אנליסט/ית אפיון**
  ו-**DevOps/QA** — עדיין לא הוקמו.

- **What was done:** רונן ביקש עובד שיידע לעבוד עם אתרי וורדפרס. הצגתי הערכה
  (וורדפרס הוא תפקיד נפרד ולא הרחבה של עומר/נועם) וביקשתי שלוש הכרעות: שם, סקופ,
  ורמת גישה לאתר חי. נבחרו **דנה** (נקבה, גוף שני "את"), **שלושה תחומי אחריות**
  ללא WooCommerce, ו**קריאה חיה + כתיבה באישור**.
  נוצר `.claude/agents/dana.md` (220 שורות) בפורמט הצוות: חוק ברזל, סעיף סודות
  מחמיר, סטאק, שלושה תחומי אחריות, 8 עקרונות ליבה, שלושה flows נפרדים (אתר חדש /
  תחזוקה / תוכן+SEO), QA, שער עדי, מבנה פלט וגבולות. עודכן `CLAUDE.md`: הצוות גדל
  ל-10 דמויות/9 עובדים, דנה נוספה לרוסטר עם trigger keywords וכלל ההבחנה
  עומר/נועם/דנה, נוספה זרימת "אתר וורדפרס", נוספה שורת שער לעדי, ועודכן מבנה
  התיקיות. נוצר `dana/README.md` + `dana/Outputs/`.

- **Decisions:**
  - **תפקיד נפרד ולא הרחבת עומר** — אותו היגיון שהפריד את נועם מעומר
    ([[team-expansion-noam-fullstack]]): עומר נשאר קליל וממוקד בסטטי מהיר, ומי
    שנוגע ב-CMS ובאתרים חיים מקבל בעל-בית משלו.
  - **כלל ההבחנה הוא "מי מתחזק את התוכן אחרי המסירה"** — ולא "כמה מסכים" או "יש
    מסד נתונים". אם הלקוח נכנס ועורך בעצמו בלי מפתח → דנה. זו ההבחנה שמחזיקה גם
    כשאתר WP קטן מדף נחיתה של עומר.
  - **קריאה חיה מותרת, כתיבה חסומה** (בחירת רונן מתוך שלוש רמות גישה) — כי אבחון
    מהזיכרון הוא כשל מקצועי, אבל אתר חי הוא **פעולה בלתי-הפיכה**. הפשרה: לקרוא כמה
    שרוצים, ולכתוב רק דרך אישור.
  - **"מכינה את הפעולה" הוגדר בשלושה חלקים חובה** — הפקודה המדויקת, הגיבוי הקיים
    **לפני**, ודרך החזרה אחורה. בלי שלושתם הפעולה לא נחשבת מוכנה. זו החמרה מכוונת
    מעל הנוסח של מאיה/טל, כי הנזק כאן הפיך פחות.
  - **WooCommerce נשאר בחוץ** — רונן לא בחר בו. מונע מדנה להיות "מומחית לכל דבר
    WP" ומשאיר את התפקיד חד.
  - **Block Editor כברירת מחדל, לא Elementor** — באתר חדש; באתר קיים עובדים בתוך
    מה שכבר יש ולא ממירים בלי החלטה. הימנעות מנעילה לספק.

- **Notes / Caveats:** דנה הוקמה **לפני** שיש לה תיק אמיתי — בניגוד לנועם, שהוקם
  אחרי שעומר כבר חרג מהגדרת התפקיד שלו ב-[[basketball-scheduler-cloud-migration]].
  זה אומר שהקונבנציות שלה הן הצעה ולא ניסיון. סעיף הסודות נכתב מחמיר במיוחד בגלל
