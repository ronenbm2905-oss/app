# טופולוגיית ריפואים — מתי פרויקט מקבל git משלו

## Overview

הכלל שלפיו מחליטים אם תוצר נשאר בריפו הצוות (`ronenbm2905-oss/app`, **ציבורי**) או יוצא לריפו עצמאי,
והמצב בפועל של הפרויקטים תחת `Output/`.

**הנתיב המקומי של ריפו הצוות במחשב של רונן (Windows):** `C:\Users\RONEN\Desktop\cloud ai\app`
(מרכאות חובה — יש רווח ב-`cloud ai`). כל תיקיות `Output/` יושבות תחתיו. תועד 19.8.2026, אחרי
שסשן ענן לא ידע לכתוב נתיב מלא בבלוק פקודות ל-deploy.

**הכלל:** **ריפו לכל יעד deploy.** אם משהו מתפרסם בנפרד — Netlify, Firebase Hosting, דומיין משלו — הוא מקבל ריפו.
אם הוא תוצר סטטי-מסמכי בלי deploy עצמאי (דף נחיתה בודד, בריף, קופי, מצגת) — הוא נשאר בריפו הצוות.

**סימני היכר לריפו נפרד:** `package.json` + build · לקוח מקבל את הקוד · דרוש היסטוריה/issues נפרדים · הרשאות שונות מהצוות.

**המלכודת המרכזית:** `git init` בתוך תיקייה שכבר יושבת בריפו-האב מייצר ריפו מקונן, ואם הקבצים
כבר נוספו לאינדקס של האב — הם מנוהלים **פעמיים**. שתי דרכים נכונות: להוציא את הפרויקט לתיקייה
מחוץ ל-`app/`, או להשאיר במקום ולהחריג ב-`.gitignore` של האב.

## Open Questions

- **`property-management` מנוהל בשני ריפואים במקביל** — 66 קבצים באינדקס של `app` **וגם** ריפו משלו שדוחף
  ל-`ronenbm2905-oss/property-management`. טרם תוקן. הפתרון: `git rm -r --cached` באב + `.gitignore`.
- **`basketball-scheduler` ו-`haderech-lamilim` טרם הוצאו** — שניהם מוצרים חיים עם deploy עצמאי
  (Firebase / Netlify) ועדיין יושבים באינדקס של ריפו הצוות (70 ו-~? קבצים).
- **`fleet-management` — ריפו מקומי בלי remote.** יש לו `.git` וקומיט אחד, אין לו לאן לדחוף.
- **שלושה פרויקטים הם build בלבד, הקוד חסר:** `absolut-diamonds`, `mas-shevach-leads`, `nrcar` —
  רק `dist/` ו-`functions/lib` (JS מקומפל). אין `src/`, אין `package.json`. **לבדוק שחזור לפני כל החלטת ריפו.**
- **הריפו של הצוות ציבורי** — כל החלטה על הוצאת פרויקט צריכה לשקול מה כבר חשוף שם.

    ו-Run2dream שלא היה ב-`main` בכלל.

- **Decisions:**
  - **הכלל הוא "יעד deploy" ולא "גודל" ולא "יש בו קוד".** דף נחיתה סטטי הוא קוד, ובכל זאת נשאר בצוות —
    כי אין לו חיים משלו. הקריטריון הוא **האם משהו חי מצביע עליו**.
  - **מוציאים החוצה, לא מקננים.** `run2dream/` נוצר כאח של `app/` ולא כתת-תיקייה. ריפו מקונן עובד רק
    כשמלווים אותו ב-`.gitignore` באב, וזה מנגנון ששוכחים.
  - **הכלל תקף גם למקום שבו הקוד יושב בתוך הריפו** — לא רק אילו קבצים, אלא **באיזה ענף**. ראה למטה.

- **Notes / Caveats:**
  - **הלקח המרכזי, והוא לא על ריפואים אלא על ענפים: ענף אינו מקום אחסון.** ארבעה פרויקטים —
    NRCAR, fleet, mas shevach ו-Run2dream — ישבו בענף בשם `absolut-diamonds-design-language`,
    שנקרא על שם פרויקט חמישי. **Run2dream היה חי באוויר** ובכל זאת נגיש רק למי שזכר את שם הענף השגוי.
    `main` הראה תיקייה ריקה. **הריפו לא איבד כלום; הטופולוגיה הסתירה הכול.**
  - **שם התיקייה משנה יותר ממה שנדמה.** טעות ההקלדה `runf2dream` גרמה לכך שחיפוש טקסט על
    `run2dream` החזיר אפס תוצאות — הפרויקט "נעלם" בגלל אות אחת.
  - **`git status` הראה `Output/fleet-management` כ-untracked** למרות שיש בפנים ריפו שלם עם קומיט.
    זו התנהגות תקינה של git מול ריפו מקונן, והיא **נקראת כמו "אין כאן כלום"**.
