# קטלוג תכשיטים ויהלומים — אפליקציית ווב (פרוסה 1)

קטלוג צד-לקוח עם **קונפיגורטור**: הלקוח בוחר דגם, בוחר יהלום מהמלאי, רואה מחיר
מלא ומפורק — ופונה בוואטסאפ או בטופס.

> ⚠️ **האפליקציה אינה מוכנה לעלייה לאוויר.** יש חוסמים משפטיים ותפעוליים פתוחים.
> ראו [מה חוסם עלייה לאוויר](#מה-חוסם-עלייה-לאוויר).

---

## הרצה מהירה (בלי Firebase)

```bash
npm install
npm run dev
```

האפליקציה עולה במצב **הדגמה מקומי**: 10 דגמים, 26 אבנים ונתוני קשר לדמו, הכול
ב-`localStorage`. מסך הניהול (`#/admin`) פתוח בלי התחברות. זה מספיק כדי לבדוק את
כל הזרימות — כולל הקונפיגורטור, הסינון והטופס — לפני שמקימים ענן.

```bash
npm run build          # בנייה לייצור
npm run render:check   # 78 בדיקות רינדור, כולל בדיקות הציות המשפטי
```

## מודל הנתונים — למה שני אוספים ולא אחד

זו **ההחלטה המבנית המרכזית**, והיא ישירות מסקירת עדי (A1):

| | `models` — דגם | `diamonds` — אבן |
|---|---|---|
| `listingType` | `made_to_order` | `specific_stone` |
| מה זה | עיצוב שמיוצר לפי הזמנה | אבן פיזית אחת שקיימת במלאי |
| תמונת המחשה | ✅ מותרת, **עם תווית על גבי התמונה** | 🔴 **אסורה** |
| מספר תעודה | 🔴 **אסור** — התעודה שייכת לאבן | ✅ חובה, יחד עם קובץ התעודה |
| 4C | טווחים בלבד (`caratRange`) | ערכים מדויקים |
| מחיר | "החל מ־", **מחושב** מהמלאי הזמין | מחיר האבן הזאת |

**המחיר אינו שדה — הוא מחושב:**

```
מחיר = שיבוץ (בסיס + תוספת סוג זהב + תוספת גוון) + מחיר האבן × מספר האבנים
```

`stoneCount` קיים כי צמודי אוזן צורכים שתי אבנים — בלעדיו העגילים מתומחרים
בחצי מחיר.

**כל הסכומים באגורות שלמות** (`priceAgorot`), תמיד כוללי מע"מ. אם האדמין מזין
מחיר ללא מע"מ, האפליקציה מנרמלת בשמירה ומציגה רק את המחיר הכולל.

## הקמת Firebase

1. **צרו פרויקט** — ⚠️ **במזהה ניטרלי** (למשל `ab-atelier-catalog`).
   מזהה פרויקט אינו ניתן לשינוי, והוא זולג ל-URL, לקונפיג ולתיעוד. אל תשתמשו
   בשם המותג לפני clearance (A9.3).
2. **Firestore** ב-production mode, region **`me-west1`**.
3. **Authentication** → הפעילו **Google**. אין ספק הרשמה אחר — אין חשבונות לקוח.
4. **Storage** → הפעילו.
5. **רשמו Web app** והעתיקו את הקונפיג ל-`.env` (העתיקו מ-`.env.example`).
6. **צרו את מסמכי האדמין** — לכל מנהל, מסמך ריק בנתיב `admins/{uid}`.
   ה-uid מופיע ב-Authentication → Users אחרי כניסה ראשונה.
7. **פרסמו את הכללים** (ראו למטה).
8. **אשרו את ה-DPA של Google** בחשבון (O6) — פעולת חשבון, לא קוד.
9. **הפעילו App Check** עם reCAPTCHA v3 (A6.3) — נקודת הכתיבה של `leads`
   פומבית, ובלי App Check זהו endpoint כתיבה חופשי.

```bash
npm run build
# ⚠️ ה-deploy נחסם ל-Claude. הריצו ידנית:
cmd /c "npx firebase-tools deploy --only hosting,firestore:rules,storage"
```

**גילויים:**
- `VITE_*` נצרבים ל-build → כל שינוי קונפיג מחייב `npm run build` מחדש.
- `.env` אינו ב-git → בכל מחשב חדש צריך ליצור אותו מ-`.env.example`.
- **אל תבנו כשקיים `.env` של מצב מקומי** — זה מייצר build עם Firebase מנוטרל
  שנראה כמו אובדן נתונים.

## מה חוסם עלייה לאוויר

### 🔴 משפטי — לפני deploy

- [ ] **נוסחי מדיניות פרטיות, תנאי שימוש והצהרת נגישות** (L1, L2). כרגע ריקים,
      והמסכים מציגים באנר טיוטה. נכנסים דרך `settings.legal` — לא דרך קוד.
- [ ] **מעמד IGI כמעבדה מאושרת בישראל** (L4) — לא אומת. `CERT_LABS` נעול
      ל-IGI/GIA; אם IGI אינה מאושרת, זו בעיה בכל אבן.
- [ ] **App Check** — לא מופעל.
- [ ] **אימות ה-rules באמולטור** (A6.8): אנונימי קורא `leads`; אנונימי כותב ליד
      עם שדה `status`; אנונימי קורא פריט `hidden`. **טרם בוצע.**
- [ ] **clearance לשם המותג** (L6) — לפני נעילת שם, דומיין ומייל.
- [ ] **תקופות שמירה ללידים** (L7).

### 🟠 תפעולי — חסר מהלקוח

- [ ] **מספר וואטסאפ עסקי** — כרגע מספר דמו (`972500000000`). מסך ההגדרות מתריע.
- [ ] **זהות העוסק** (U2) — שם, ח.פ. וכתובת. נדרשים במסמך הגילוי לפי תקנות 1995,
      ולכן נכנסים להודעת הוואטסאפ.
- [ ] **רכז נגישות** (U1) — שם, מייל וטלפון.
- [ ] מייל, לינקים לרשתות, דומיין.

### 🟡 לא נבנה בפרוסה הזאת

העלאת תמונות (Storage) — הסכימה מוכנה (`images[]` עם `isStock`, `alt`, `license`)
אבל ה-UI להעלאה במסך הניהול לא נבנה; כרגע דגמים מקבלים איורים מנתוני הדמו
ואבנים מוצגות באיור סכמטי · ייבוא CSV למלאי אבנים · עריכת FAQ במסך הניהול
(עריכת hero וסיפור כן קיימת) · `optOut` ורשימת השתקה (A7.3).
