>   לא נגע במסמך הזה בכוונה: ה-`at` שלו סופר לילות שנשמטו.

> **`run-nightly.cmd` נשאר כהפעלה ידנית בלבד** — המשימה המתוזמנת ב-Windows מיותרת.

## למה זה בנוי דווקא ככה

האפליקציה שומרת את כל נתוני המועדון ב**מסמך אחד**, וכל שמירה כותבת אותו **בשלמותו**
(`useClubData.js` → `setDoc`). תהליך אוטומטי שכותב לשם בזמן שאתה עורך לוח **מוחק את העריכה
שלך בלי שגיאה ובלי עקבות**.

לכן התהליך הלילי **לעולם לא נוגע במסמך המועדון**. הוא כותב רק ל-`clubs/main/pendingImports/{תאריך}`.
הכתיבה היחידה למועדון נשארת מה שהיא תמיד הייתה: לחיצה שלך, כשאתה מסתכל על המסך.

## הקמה — פעם אחת

### 1. מפתח service account — ייעודי, לא של הפרויקט

**אל תשתמש במפתח ה-"Firebase Admin SDK" הרגיל.** הוא נושא הרשאות פרויקט מלאות: Firestore,
Storage, Authentication, ואפילו הנפקת טוקן התחברות בשם כל משתמש. התהליך צריך לקרוא מסמך אחד
ולכתוב לתת-אוסף אחד.

Google Cloud Console → **IAM & Admin → Service Accounts** → **Create service account**:
- שם: `basketball-nightly-sync`
- תפקיד: **Cloud Datastore User** (`roles/datastore.user`) — זה כל מה שהוא מקבל
- ואז לשונית **Keys → Add key → JSON**

שמור כאן, מחוץ לפרויקט:

    %USERPROFILE%\.basketball\nightly-sync.json

**מה הצמצום באמת נותן** — נמדד ב-26.8.2026, לא הונח:

| פעולה | מפתח הפרויקט | המפתח הייעודי |
|---|---|---|
| קריאת חמשת שדות הלוח | ✅ | ✅ |
| כתיבה ל-`pendingImports` | ✅ | ✅ |
| רשימת משתמשי Authentication | ✅ | 🔒 נחסם |
| מחיקת משתמש | ✅ | 🔒 נחסם |
| Storage והגדרות פרויקט | ✅ | 🔒 נחסם |

**שתי הסתייגויות, כדי שלא יתגלו בדיעבד:**

1. **קריאת המסמך המלא עדיין אפשרית.** ל-IAM אין הרשאות ברמת שדה — `roles/datastore.user`
   מתיר קריאה של המסד כולו. מה שמונע מנתוני הקטינים לצאת הוא ה-`.select()` **בקוד**
   (`prepare-import.mjs` → `readClub`), ולא התפקיד. אל תסיר אותו.
2. **הנפקת טוקן בשם משתמש עדיין אפשרית**, כי ה-SDK חותם מקומית עם המפתח הפרטי ואינו פונה
   ל-IAM. זה נכון לכל מפתח service account, ולכן ההגנה כאן היא מיקום הקובץ והיכולת לבטל אותו
   מיידית — לא התפקיד. (לא בדקתי אם Firebase אכן מקבל טוקן כזה: בדיקה מוצלחת הייתה יוצרת
   משתמש אמיתי בפרודקשן.)

> ⚠️ הריפו **ציבורי**. הקובץ הזה לא נכנס אליו ולא נשלח במייל או בוואטסאפ. אם הוא דלף —
> מוחקים את המפתח בקונסולה ומנפיקים חדש, פעולה של דקה.

### 2. התלות

```
npm install firebase-admin --save-dev
```

### 3. בדיקה ידנית לפני שמתזמנים

```
node scripts\fetch-federation.mjs
node scripts\prepare-import.mjs --dry
```

`--dry` לא כותב לענן ולא דורש מפתח; הוא שומר `federation-inbox\proposal-<תאריך>.json`
כדי שתראה בדיוק מה היה נכנס.

### 4. המשימה המתוזמנת

Task Scheduler → **Create Task** (לא Basic):

- **General:** Run whether user is logged on or not · Run with highest privileges
- **Triggers:** Daily, 03:00
- **Actions:** Start a program →
  `C:\Users\RONEN\Desktop\cloud ai\app\Output\basketball-scheduler\scripts\run-nightly.cmd`
- **Settings:** ✅ Run task as soon as possible after a scheduled start is missed

הסעיף האחרון הוא מה שמציל אותך כשהמחשב היה כבוי — המשימה תרוץ בהדלקה הבאה במקום לדלג על היום.

## מה נשמר כשמאשרים

- **שעות שהזזת ידנית** (`timeOverride`) ו**כתובות שהזנת** (`addressOverride`) — נשמרות.
- **משחק שבוטל** מסומן ונשאר בלוח עם קו חוצה. הוא **לא נמחק**: מאמן שכבר ראה אותו צריך לדעת
  שהוא ירד. הוא מוחרג מייצוא ההסעות ומייצוא היומן.
- **משחק שהאיגוד מחזיר** חוזר להיות רגיל לגמרי.
- ההצעה מוחלת על מה שיש **ברגע האישור**, לא על צילום מ-03:00 — כך עריכה שעשית ב-08:00 לא נדרסת.

## כשמשהו נראה מוזר

**באנר כתום "הקובץ נראה חלקי"** — יותר מ-15% מהמשחקים בטווח היו מסומנים כמבוטלים. כך נראה קובץ
של ליגה אחת או הורדה שנקטעה, ולא סבב ביטולים אמיתי. **אל תאשר לפני שעברת על הרשימה.**
כדי לאשר בכל זאת צריך לסמן במפורש שבדקת.

**אין באנר כמה ימים** — פתח את `log.txt`. אם כתוב `FAILED` כמה ימים ברצף, האיגוד כנראה שינה
משהו. הרץ ידנית את שלב 1 ותראה את השגיאה. הקובץ נדחה גם אם ירד בהצלחה אבל חסרות בו העמודות
שאנחנו צריכים — זה מכוון.

**עצירה זמנית:** Task Scheduler → Disable. שום דבר באפליקציה לא תלוי בזה; הייבוא הידני
ממשיך לעבוד בדיוק כמו קודם.

## עונות — למה זה עובד לבד

האתר בנוי על SportsPress, ויש בו API ציבורי: `/wp-json/sportspress/v2/seasons`.
נכון ל-25.8.2026 העונה האחרונה שם היא **2025-2026** (`id=119472`), ו-2026-2027 עדיין לא נפתחה.

**היצוא לא מקבל פרמטר עונה.** נבדק: `&seasons=18985` ו-`&seasons=119472` מחזירים בדיוק
את אותם 450 משחקים. הכתובת מחזירה תמיד את **העונה הנוכחית באתר** — ו-`club/1071/` עושה 301
ל-`club/1071-2/`, כלומר ה-`-2` הוא ארטיפקט של WordPress ולא סמן עונה. לכן כשהאיגוד יפתח את
העונה החדשה, אותה כתובת תחזיר אותה בלי שנגע בכלום.

**המעקה שמוודא את זה:** אם כל המשחקים בקובץ כבר עברו, לא נוצרת הצעה, ובלוג נכתב במפורש:

```
the file still covers a finished season (19.10.2025 → 23.6.2026) — the federation has not
published the new one yet. No proposal filed.
```

כך שאפשר להפעיל את המשימה כבר עכשיו: היא תרוץ כל לילה בשקט, ותתעורר לבד ביום שהעונה החדשה
תעלה. אם תרצה בכל זאת לייבא עונה שהסתיימה — `node scripts\prepare-import.mjs --allow-past`.
