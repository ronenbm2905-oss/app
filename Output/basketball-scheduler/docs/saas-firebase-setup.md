# הקמת פרויקט Firebase לגרסה הרב-אגודתית (פעם אחת)

> **סטטוס: הפרויקט הוקם ב-8.8.2026 — `basketball-all`** (מספר 708870616186, אזור `me-west1`).
> שלבים 1–5 **בוצעו**: Firestore נוצר, Google sign-in הופעל, אפליקציית Web נרשמה
> (`1:708870616186:web:96e583d0611518f5b577c3`), `.env.saas` מולא ו-`.firebaserc` מצביע על הפרויקט.
> ממשיכים משלב 6 — פרסום חוקי האבטחה.

מדריך הקמה חד-פעמי לפרויקט החדש, שישרת את **כל** האגודות. הפרויקט הקיים של קרית אונו
(`basketball-schedule-f0f57`) לא נוגעים בו.

> **למה פרויקט נפרד ולא אותו אחד:** מרגע שאגודה אחרת משתמשת, הנתונים שלה יושבים בפרויקט. פרויקט
> שנפתח עבור עמותת קרית אונו הוא מקום לא נכון לאחסן בו נתונים של אגודות אחרות — וזה בדיוק מה
> שהשער המשפטי בוחן. בנוסף: חיוב נפרד, הרשאות נפרדות, ותקלה בפיתוח לא נוגעת במערכת החיה.

## 1. יצירת הפרויקט

[console.firebase.google.com](https://console.firebase.google.com) → **Add project**.

- שם: משהו ניטרלי שמתאים למוצר, לא לאגודה מסוימת (למשל `basketball-scheduler-saas`).
  שם הפרויקט מופיע בכתובת שכל הלקוחות יראו.
- Google Analytics: אפשר לוותר. אם מפעילים — זה איסוף מידע נוסף שידרוש התייחסות במדיניות הפרטיות.

**התוכנית החינמית (Spark) מספיקה.** Firestore, Auth עם Google, ו-Hosting כלולים בה. מה שהיה
מחייב שדרוג בתשלום — אימות ב-SMS, Cloud Functions והתראות Push — לא בשימוש כאן.

## 2. Firestore

**Build → Firestore Database → Create database**

- מצב: **Production mode** (החוקים שלנו נפרסים בשלב 6 וגוברים ממילא).
- אזור: **me-west1 (תל אביב)**. האזור **לא ניתן לשינוי** אחרי היצירה, והוא רלוונטי משפטית —
  מיקום אחסון המידע מוצהר במדיניות הפרטיות. אחסון בישראל מוציא לגמרי את שאלת ההעברה
  החוצה-גבולות, וזה חשוב במיוחד כשמדובר בנתונים של קטינים.
  (הפרויקט של קרית אונו יושב ב-`eur3` — מי שיעבור למערכת הזו, המידע שלו יעבור לישראל.)

## 3. Authentication

**Build → Authentication → Get started → Sign-in method**

- **Google** — הפעל. זה מה שמשמש גם מנהלים ומאמנים וגם הורים בפורטל.
- **Email link (passwordless)** — אופציונלי, מומלץ בהמשך: הורה בלי חשבון Google לא נחסם.
- **Settings → Authorized domains** — ודא שהדומיין של האתר החדש מופיע (מתווסף אוטומטית).

## 4. רישום אפליקציית Web + `.env.saas`

**Project settings (⚙) → General → Your apps → Web (`</>`)**

רשום אפליקציה, העתק את אובייקט ה-config, והעבר ל-`.env.saas` בתיקיית הפרויקט
(העתק מ-`.env.saas.example`).

> **חובה למלא את כל שישה המפתחות.** Vite טוען את `.env` **תמיד**, גם עם `--mode saas` — כל מפתח
> שיישאר ריק ייפול חזרה לערך של קרית אונו. `vite.config.js` חוסם את זה ומפיל את ה-build, אבל
> עדיף למלא נכון מלכתחילה.

הגדר גם `VITE_CLUB_ID=demo` — כך שהכתובת הראשית תצביע על מועדון הדגמה ולא על נתונים אמיתיים.

## 5. חיבור ה-CLI לפרויקט

ב-`.firebaserc`, החלף את `REPLACE-WITH-NEW-PROJECT-ID` במזהה הפרויקט האמיתי (Project settings →
Project ID). שים לב ש-`default` מנוטרל בכוונה — כל פריסה חייבת `--project` מפורש.

## 6. פרסום חוקי האבטחה — לפני שנכנס נתון ראשון

בחלון cmd אמיתי (Win+R → `cmd`), מהתיקייה `Output\basketball-scheduler`:

```bash
node ".\node_modules\firebase-tools\lib\bin\firebase.js" deploy --only firestore:rules --project saas
```

## 7. מסמכי האתחול (בקונסולה)

**א. הרשאת הקמת מועדונים** — אוסף `config`, מסמך `global`:

```json
{ "superAdmins": ["ronenbm2905@gmail.com"] }
```

**ב. מועדון הדגמה** — אוסף `clubs`, מסמך `demo`, לפי `new-club-template.json` שבתיקייה הזו.
ודא ש-`admins` מכיל את הכתובת שלך **באותיות קטנות**.

## 8. build ופריסה ראשונה

```bash
npm run build:saas
```

```bash
node ".\node_modules\firebase-tools\lib\bin\firebase.js" deploy --project saas
```

## 9. בדיקת קבלה

- [ ] `/` נטען ומציג את מועדון הדגמה (לא את קרית אונו)
- [ ] `/c/demo` עולה, ואתה מזוהה כמנהל (טאב "הגדרות" מופיע)
- [ ] כתובת שאינה ב-`admins`/`members` מקבלת הודעת "אין הרשאת גישה"
- [ ] `/c/demo` → הגדרות → פורטל הורים → "צור קוד" לקבוצה
- [ ] לוח שבועי → "פרסם לו״ז לשבוע" → ב-Firestore נוצר `clubs/demo/published/<שבוע>`.
      **פתח את המסמך וּודא שאין בו שמות שחקנים, טלפונים או תאריכי לידה**
- [ ] בדפדפן נפרד / גלישה בסתר: `/c/demo/portal` → התחברות Google עם חשבון **אחר** → הזנת הקוד →
      מוצג הלו״ז. זהו המסלול שמעולם לא נבדק — ראה למטה
- [ ] אותו חשבון הורה מנסה לגשת ל-`/c/demo` → נחסם

> **הבדיקה הקריטית היא האחרונות.** כל מסלול הענן של הפורטל (כניסת הורה, פתירת קוד ההצטרפות,
> וכתיבת `portalUsers`) נבנה אך **מעולם לא רץ** — במצב מקומי הוא נפתר בקיצור דרך. זה המקום
> הראשון שבו צפויות תקלות, לא בממשק.

## מה שלא צריך להפעיל

- **Storage** — לוגו המועדון נשמר כתמונה מוקטנת בתוך מסמך המועדון, בדיוק כדי לא להזדקק לו
  (וכדי להימנע מבעיות CORS בייצוא תמונות לוואטסאפ).
- **Cloud Functions / Push** — לא בשימוש. התראות הן באנר בתוך האפליקציה.
