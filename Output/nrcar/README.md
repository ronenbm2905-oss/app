# NRCAR — הרכב שלי

כל מה שצריך לזכור ולנהל ברכב הפרטי, במקום אחד: טסט, ביטוח, טיפולים, מסמכים
ותזכורות — ובכפתור אחד, **מסך חירום** עם כל המסמכים לזירת תאונה.

- **קהל היעד:** מיינסטרים ישראלי, בדגש כבד על מבוגרים. "מבחן הסבתא" הוא דרישת-על.
- **פלטפורמה:** ווב/PWA מובייל-פירסט (Vite + React 18 + Tailwind 3 + Firebase, JavaScript).
  מתוכנן כך שאותו קוד ייעטף ב-Capacitor בהמשך — **לא מוסיפים Capacitor עכשיו.**
- **סטטוס:** פרוסה 1 מלאה + **פרוסה 2א** (שכבת ההובלה) — נבנתה ונבדקה מול אמולטור.

---

## הרצה מהירה

```bash
npm install
npm run dev            # http://localhost:5179
```

בלי קובץ `.env` האפליקציה רצה במצב **fallback מקומי**: משתמש בודד שהוא הבעלים,
כל הנתונים ב-`localStorage`. אפשר ללחוץ ולבדוק מיד, בלי להקים פרויקט Firebase.

> ⚠️ **מסמכים אישיים (רישיון נהיגה) חסומים במצב המקומי** — "כדי לשמור מסמכים
> אישיים צריך להתחבר לחשבון". הסיבה: base64 של רישיון נהיגה ב-`localStorage`
> הוא תעודת זהות בטקסט גלוי על הדיסק. תמונות רכב במצב מקומי — בסדר גמור.

## בדיקות

```bash
npm run smoke          # 644 אסרשנים — המנוע, חוסמי הפרטיות, רצף כתיבות, סריקות
npm run render:check   # 217 אסרשנים — רינדור אמיתי של כל המסכים (React SSR)
npm run build          # 1591 מודולים
npm run e2e            # 35 אסרשנים — QA חי בדפדפן אמיתי (דורש build קודם)
```

ובנוסף, מול **אמולטור Firebase אמיתי** (מקומי לחלוטין; אין כאן deploy):

```bash
npm run emu:rules      # 99 אסרשנים — אכיפת firestore.rules ו-storage.rules
npm run emu:cloud      # 42 אסרשנים — onSnapshot, writeHouseholdDiff, Storage
npm run emu:functions  # 98 אסרשנים — ה-scheduler, ההסלמה, signed URLs
npm run emu -- "<cmd>" # להריץ פקודה כלשהי בתוך האמולטורים
```

**שש שכבות, כי אף אחת לא מספיקה.** `smoke` בודק פונקציות טהורות,
`render:check` רינדור אחד, `e2e` לוחץ על מסך אמיתי, ו-`emu:*` מריץ מול
Firestore, Storage ו-Functions אמיתיים. כל שכבה תפסה באג שהשכבות שמעליה פספסו:
איבוד הנתונים נתפס רק ב-`e2e`, ודליפת המסמכים האישיים ב-Storage — רק
ב-`emu:rules`.

### 🔴 `emu:rules` הוא תנאי סף, לא המלצה

**`rules` הם ארטיפקט זמן-ריצה ואינם ניתנים לאימות סטטי.** אפשר לקרוא אותם,
לסקור אותם ולסרוק אותם — ועדיין לפספס פרצה שנפתחת רק כשמנוע ההערכה מריץ
אותם. זה בדיוק מה שקרה כאן: כלל אחד "ליתר ביטחון" ביטל את בידוד המסמכים
האישיים, ו-608 אסרשנים סטטיים לא ראו אותו.

לכן, בדרישת השער של עדי: **בלי `npm run emu:rules` ירוק, לא עולים לאוויר.**

### הרצת האמולטור — מה צריך

אמולטורי Firestore ו-Storage הם **Java** (ה-Auth הוא Node בלבד), ו-
`firebase-tools` דורש **JDK 21+**. `firebase-tools` מותקן כ-devDependency של
הפרויקט ולא גלובלית — התקנה גלובלית שבורה כבר גרמה ל-`MODULE_NOT_FOUND`.

אם אין JDK במכונה, התקנה **ניידת** בלי לגעת ב-PATH או ברישום:

```bash
# 1. הורידו JDK 21 (zip) מ-https://adoptium.net וחלצו לתיקייה כלשהי
# 2. הצביעו עליה והריצו:
NRCAR_JAVA_HOME="C:/path/to/jdk-21" npm run emu:rules
```

`scripts/emu.mjs` מאתר את ה-JDK לפי `NRCAR_JAVA_HOME` → `JAVA_HOME` →
מיקומים מוכרים, ומוסיף אותו ל-PATH של תת-התהליך בלבד. אם לא נמצא — הוא יוצא
בקוד 2 עם הוראות, **ולא מדווח כאילו הבדיקות רצו**.

`e2e` מריץ Edge/Chrome ב-headless מעל CDP, דרך ה-WebSocket המובנה של Node —
**בלי puppeteer ובלי playwright ובלי שום תלות נוספת.** הוא מבצע את הזרימה
הקריטית מקצה לקצה, כולל קריאת רשת אמיתית ל-data.gov.il, וקורא את
`localStorage` אחרי השמירה. אם אין דפדפן מותקן הוא יוצא בקוד 2 ואומר זאת —
ולא מדווח כאילו רץ.

`npm run smoke` הוא לא "בדיקת יחידה" רגילה. הוא אוכף גם דברים שאי אפשר לבדוק
בקריאה לפונקציה:

- אין `navigator.geolocation` בשום קובץ
- אין `text-xs` / `text-slate-400` / `text-gray-400` / `text-stone-400` בשום `.jsx`
- ב-`<meta viewport>` אין `user-scalable` ואין `maximum-scale`
- `getDownloadURL` מופיע **רק** ב-`src/utils/files.js`
- אין ב-`.rules` שום השוואה בין `hid` לבין `request.auth.uid`
- parity מלא של מפתחות `he`/`en`
- אין `firebase deploy` בשום npm script

הסריקות מסירות הערות לפני הבדיקה — אחרת כל הערה שמסבירה *למה* משהו אסור
הופכת בעצמה לכשל, והתוצאה היא שמפסיקים לתעד.

## החלטות שנראות מוזרות — ולכן מתועדות

**1. "באיחור" גובר על "בטיפול".**
`manualStatus: "inProgress"` אומר שהמשתמש קבע תור. ברגע שהתאריך עבר, הרכב לא
עבר טסט בפועל, ועקרון "אמינות לפני הכול" מחייב לומר *באיחור*. זה נראה כמו באג,
ולכן יש לו אסרשן מפורש ב-smoke ומחרוזת שמסבירה למשתמש למה
(`task.status.overdue.hintFromInProgress`).

**2. הריווח "מנופח" ב-12.5%.**
`html { font-size: 112.5% }` = בסיס 18px, ולכן כל יחידת rem של Tailwind גדלה.
`min-h-14` הוא 63px ולא 56px. **זה מכוון** (מפרט איתי §3.3) — אל "תתקנו"
ל-`min-h-[56px]`.

**3. `text-xs` פשוט לא קיים.**
`fontSize` מוגדר ברמת `theme` ולא ב-`extend`, ולכן המחלקה לא נפלטת. העברתה
ל-`extend` מחזירה אותה לחיים בשקט.

**4. `hid` הוא מזהה אטום.**
הוא נזרע מה-uid של הבעלים, אבל **התפקיד נקרא ממפת `members`** ולא מהשוואת
מזהים. שני תרחישים ודאיים שוברים את הקיצור: בעלים שני (בני זוג), והעברת בעלות
— שהיא תרחיש ודאי במוצר לקהל מבוגר.

**5. `{vehicle}` הוא הכינוי, לעולם לא מספר הרישוי.**
"הטסט של האוטו של אמא" מול "הטסט של 12-345-67". השני נשמע כמו הודעה מהעירייה.

**6. אין service worker בפרוסה 1.**
SW שמקושש לא נכון נועל משתמש מבוגר על build ישן בלי דרך התאוששות. עמידות
האופליין של מסך החירום מושגת דרך `localStorage`, לא דרך SW.

**7. שתי שורות ה-overdue מנוסחות בשם החוק — וזו הכרעה של עדי.**
`"החוק אוסר לנהוג ברכב שאין לו ביטוח חובה בתוקף"` ו-`"לפי החוק, נהיגה ברכב
מחייבת רישיון רכב (טסט) בתוקף"` מייחסות את ה**כלל** לחוק ומשאירות את
ה**עובדה** אצלנו — ולכן לצדן יושבת תמיד **שורת ייחוס-עובדה** ("לפי מה שהזנת
באפליקציה", "לפי נתוני משרד התחבורה מ-…") **ופעולת תיקון בלחיצה אחת**. נוסח
מהסס נדחה במכוון: הוא מזמין את המשתמש להמציא חריגים.
שלושה דברים נעולים ונאכפים ב-smoke: אין `"החוק"`/`"אסור"` בשום מפתח
`comprehensive` (נהיגה בלי מקיף מותרת לחלוטין), אין שום מחרוזת שטוענת שטסט
שפג **מבטל את הביטוח** (תלוי-פוליסה), ושתי השורות לא מתמזגות.

**8. `text-3xl` (40px) שמור למספר הרישוי במסך החירום, ורק לו.**
הוא הדבר הראשון שנמסר בזירת תאונה.

**9. 🔴 המצב חי ב-`utils/store.js`, והמצביע שלו מתקדם *בכתיבה* — לא ברינדור.**
זו לא העדפה סגנונית אלא תיקון לבאג **איבוד נתונים**: קודם `useData` החזיק
`dataRef.current = data` בגוף הרכיב, כלומר המצביע התעדכן רק אחרי רינדור. שתי
קריאות `update()` באותו handler (הוספת רכב = `saveVehicle` + `saveTask`) רצו
באותו tick, שתיהן שכפלו את אותו מצב-קדם, והשנייה דרסה את הראשונה. התסמין:
המסך הודיע "הרכב נשמר, ופתחנו תזכורת לטסט", וב-`localStorage` היו
`vehicles: []` ומשימת טסט **יתומה**.
שתי שכבות הגנה, ובכוונה שתיהן: `store.js` הופך כל רצף כתיבות לנכון, ו-
`utils/writes.js` מבטל את הצורך בו — **פעולה מוצרית אחת = כתיבה אחת**
(`saveVehicleWithTasks`, `writeTaskCompletion`). זה חוסך גם כתיבה שנייה
ל-Firestore וגם מצב-ביניים בענן שבו משימה מצביעה לרכב שעוד לא נכתב.
נאכף ב-smoke (סעיפים 26-28) ובדפדפן אמיתי ב-`e2e`.

## פרטיות ואבטחה — מה שנבנה בכוונה

מבוסס על `adi/Outputs/2026-08-13-nrcar-privacy-by-design.md` (חוסמי-תכנון N1-N7):

- **N1** — המטמון במכשיר הוא **צלע שלישית ב-cascade**: Firestore → Storage →
  מכשיר. מפתח המטמון כולל uid (`nrcar:emergency:<uid>:<vehicleId>`), ו-
  `purgeLocalCache` נקראת ביציאה מהחשבון, בהחלפת משתמש, ובמחיקת/ארכוב רכב או מסמך.
- **N2** — `fileRef` = `{storagePath, contentType, size, uploadedAt}`. **אין URL
  בשום מקום מתמיד.** `getDownloadURL` נפתר על פי דרישה בתוך `files.js` בלבד,
  והתוצאה חיה בזיכרון. כל גישה למסמך עוברת דרך `openSensitiveDocument()`.
- **N3** — `sensitivity` על **כל** מסמך. רישיון רכב ופוליסה מסומנים
  `containsIdNumber`: "בלי ת.ז." נכון ברמת השדה ולא ברמת הקובץ.
- **N4** — התפקיד מ-`members`, לעולם לא מ-`hid == uid` (נאכף בסריקה סטטית).
- **N5** — `users/{uid}.notices` הוא מערך **append-only**.
- **N6** — `retentionClass` על כל ישות; `exportHousehold()` ו-`deleteHousehold()`
  על אותו cascade.
- **N7** — `guardianConsent` ו-`isMinor` נכתבים ע"י הבעלים בלבד, append-only,
  והזמנת קטין אינה עוברת ל-`accepted` בלי הסכמה.

**מסך החירום — חוק ברזל:** אין שום נתיב קריאה לא-מאומת. אין קישור ציבורי, אין
QR, ואין "מצב חירום" שעוקף Auth. השער נאכף **מבנית** ב-`App.jsx`: בלי משתמש,
כל המסלולים — כולל ה-shortcut מה-manifest — נוחתים על מסך הכניסה. הכרטיס עצמו
מציג **רק** רישיון רכב וביטוח חובה (דומיין `shared`) ואת רישיון הנהיגה של
המשתמש עצמו; הפוליסה (דומיין `owner`) ורישיון של אדם אחר לעולם לא. פרטי
הבעלים = **שם + טלפון בלבד**. חיוג דרך `tel:` בלבד.

**"תרגול חירום" באונבורדינג** (הנוסח של עדי, 6.3) מראה את המסך בשקט לפני
שצריך אותו, ובאותו מסך אומר את האמת: הוא נפתח בלי סיסמה, ומי שמחזיק את
הטלפון הפתוח יכול לראות אותו. זו חובת השקיפות של תיקון 13, בנקודה שבה היא
באמת נקראת.

**ארבעה דומייני Storage בנתיב עצמו, מהיום הראשון:**

```
households/{hid}/vehicles/{vid}/shared/{file}    ← רישיון רכב, ביטוח חובה
households/{hid}/vehicles/{vid}/owner/{file}     ← פוליסות, קבלות — בעלים לתמיד
households/{hid}/vehicles/{vid}/photo/{file}
households/{hid}/people/{driverId}/docs/{file}   ← אותו אדם בלבד
```

### 🔴 שני באגים שרק האמולטור תפס — ומה נלמד מהם

**1. כללי Storage הם אדיטיביים, ו"רשת ביטחון" ביטלה את כל בידוד המסמכים.**
ב-`storage.rules` היה כלל רחב `match /households/{hid}/{allPaths=**}` שנתן
לבעלים read/write "ליתר ביטחון". **התוצאה של כללי Storage היא ה-OR של כל
הכללים שמתאימים** — כלל ספציפי שאוסר אינו גובר על כלל רחב שמתיר. בפועל
הבעלים יכול היה לקרוא (ולהעלות!) את סריקת רישיון הנהיגה של כל נהג במשק
הבית — בדיוק מה ש-`personalDocs` נבנה כדי למנוע. הכלל הרחב הוסר; כל נתיב
שאינו אחד מארבעת הדומיינים נופל ל-deny הגורף. **הכלל שנשאר: אין כללים רחבים
לצד כללים מגבילים.** נאכף מעכשיו ב-smoke.

> ### ⚠️ ואם באג rules כזה עולה לאוויר — **ביטול ההרשאה אינו סוגר את האירוע**
>
> נוהל אירוע האבטחה (O8) חייב לכלול צעד מפורש שקל מאוד לפספס: **כל טוקן
> הורדה שהונפק בחלון החשיפה ממשיך לחיות אחרי שהכלל תוקן.** `getDownloadURL`
> מחזיר כתובת עם טוקן **קבוע** שאינו פג ואינו נבדק מול rules; תיקון הכלל
> מונע הנפקה **חדשה** בלבד.
>
> לכן, אחרי תיקון של פרצת rules על אובייקטים ב-Storage, נדרש צעד נוסף:
> **רוטציית טוקנים על כל אובייקט מושפע** (מחיקת/החלפת ה-`firebaseStorageDownloadTokens`
> במטא-דאטה, או מחיקה והעלאה מחדש). בלעדיו האירוע פתוח.

**2. קריאת מסמך שאינו קיים מחזירה `permission-denied`, לא "לא נמצא".**
`ensureHousehold` עשה `getDoc` ואז יצירה. אצל משתמש ענן **חדש** המסמך לא
קיים, כלל ה-read נשען על `members` שבתוכו, ההערכה נכשלת → דחייה → `getDoc`
**זורק** → הבוטסטרפ נפל בשקט (`console.warn`) ומשק הבית לא נוצר. כלומר כל
משתמש ענן חדש היה נתקע. עכשיו דחייה נחשבת "עוד לא קיים".

### ⚠️ פער ידוע שאסור לטעון אחרת עליו

ה-PRD (§8.4) דורש "קישור חתום וזמני". `getDownloadURL` של Firebase מחזיר כתובת
עם **טוקן קבוע שאינו פג**. הפער **מוקטן** בפרוסה 1 (לא שומרים URL, לא מכניסים
למטמון, לא מגיע ל-DOM, אין "שתף מסמך", והמחיקה מבטלת את הטוקן) — אבל
**הוא לא נסגר**. לכן: **מדיניות הפרטיות ותנאי השימוש של פרוסה 1 לא יטענו
"קישורים חתומים וזמניים"**, וה-DoD של ה-PRD בסעיף הזה מסומן כ**לא מתקיים**.
הפתרון האמיתי — V4 signed URLs דרך Cloud Function — נוחת בפרוסה 2, יחד עם
הזמנות הנהגים. זה תנאי לשחרורן, לא nice-to-have.

## פרוסה 2א — שכבת ההובלה (`functions/`)

הכול נבנה ונבדק **מול אמולטור בלבד**. פירוט ארכיטקטוני מלא ב-
[`functions/README.md`](functions/README.md).

### 🔴 מה המשתמש צריך לעשות כדי שזה ירוץ באמת

1. **שדרוג ל-Blaze.** תוכנית **Spark אינה מאפשרת Cloud Functions** כלל. זה
   חוסם מוחלט, ואין לו מעקף.
2. **הדלקת השליחה — שני מתגים, שניהם כבויים כברירת מחדל:**
   - `NRCAR_SENDING_ENABLED=true` (משתנה סביבה של ה-Function).
   - `config/runtime.sendingEnabled = true` ב-Firestore.
   השני הוא **מתג עצירה בלי deploy**: באג בגזירת הסטטוס כבר אינו תצוגה
   שגויה למשתמש אחד — הוא SMS שגוי לכל בסיס המשתמשים, בלתי הפיך.
   **ברירת המחדל היא לא לשלוח**, כי התקלה הקלאסית של פרוסה ראשונה בשליחה
   היא בדיקה ששולחת אלפי הודעות אמיתיות.
3. **ספק SMS וספק מייל.** אין ספקים מוגדרים. הממשק צר (`send`), וחיבור ספק
   הוא **קובץ אחד**. עד אז `deliveryState: failed` עם
   `provider-not-configured`, והסולם מסלים הלאה.
   ⚖️ לפני חתימה — שלושה קריטריונים פוסלים (עדי O14-O16): אין DPA בכתב · לא
   ניתן לדעת היכן מתבצע העיבוד · הספק שומר את גוף ההודעה לצמיתות בלי
   אפשרות הגדרה. **העדפה מעשית: ספק SMS שמעבד בישראל.**
4. **אימות מספר טלפון לפני ההודעה הראשונה** (O13) — הקוד כבר מסרב לשלוח
   ל-`channelVerified.sms !== true`, אבל **מסך האימות עצמו טרם נבנה**.
   זה הכשל היחיד כאן שאין לו מסלול תיקון עצמי: מספר שהוקלד בשגיאה שולח
   הודעות עם כינוי הרכב לאדם זר, לנצח, בלי שאיש יידע.
5. **FCM** — הצנרת קיימת; טוקני מכשיר אמיתיים דורשים אפליקציה חיה (בפועל
   Capacitor, פרוסה 3).
6. **אינדקס collection-group** על `tasks.schedule.nextFireAt` —
   ב-`firestore.indexes.json`, נפרס עם ה-rules. בלעדיו ה-scheduler נופל
   בפרודקשן ב-`FAILED_PRECONDITION`, **והאמולטור לא מתלונן**.

### שלוש הכרעות של עדי שמעצבות את המנוע

**T1 — הבעלים אינו "מוסלם אליו", הוא נמען בזכות עצמו.** אם ההסלמה נורית
*כי הנהג לא אישר*, עצם קבלתה מלמדת את הבעלים שהנהג לא אישר — ניקוי נוסח
ההודעה לא מנקה את ההסקה. לכן לבעלים סולם משלו (`[7,3,1,0]` מול `[30,14,7,3,1,0]`),
והפרדיקט הוא **`!completedAt`, לעולם לא `!acknowledgedAt`**. וזו גם ההנדסה
הנכונה: רשת הביטחון נועדה לתפוס טלפון כבוי — **הסלמה שמותנית באי-אישור לא
תופסת מקרה שבו לא הייתה מסירה כלל.**

**T3 — השדות הרגישים ירדו ממסמך המשימה.** `acknowledgedAt`, `lastFiredAt`
ו-`channelsTried[]` ישבו על מסמך שהבעלים קורא במלואו, ו-rules לא מסתירים
שדה (D1, פעם שלישית). המשימה חושפת `acknowledged` בוליאני; החותמות יורדות
ל-`tasks/{id}/private/state` — **שרת בלבד**. עם נהג יחיד על משימה,
`acknowledgedAt` הוא בדיוק "מתי הוא נגע בטלפון".

**T5 — הנמען מאומת בזמן השליחה, לא בזמן התזמון.** `recipientUid` מתיישן.
אצווה שכבר נטענה תשלח בכל מקרה, ולכן הבדיקה חייבת להיות בנקודת השליחה.
ונגזרת: `deleteHousehold()` **מאפס `nextFireAt`** לפני שהוא מוחק —
הודעה שמגיעה משירות שאדם מחק היא כשל אמון שלא מתאוששים ממנו.

## הקמת Firebase (מצב ענן)

1. **Firebase Console** → פרויקט חדש → הוסיפו אפליקציית Web.
2. Firestore ו-Storage — **באזור `me-west1`**.
3. Authentication → Sign-in method → הפעילו **Google**.
4. העתיקו `.env.example` ל-`.env` ומלאו מ-Project settings → Your apps → Web app.
5. `.firebaserc` → החליפו את `REPLACE_WITH_FIREBASE_PROJECT_ID` במזהה הפרויקט.

```env
VITE_FB_API_KEY=
VITE_FB_AUTH_DOMAIN=
VITE_FB_PROJECT_ID=
VITE_FB_STORAGE_BUCKET=
VITE_FB_SENDER_ID=
VITE_FB_APP_ID=
```

> מפתחות ה-Web ציבוריים ממילא — ההגנה האמיתית היא `firestore.rules` ו-
> `storage.rules`. **`.env` לעולם לא נכנס ל-git.**
>
> ⚠️ הערכים נקראים **בזמן build**. כל שינוי ב-`.env` מחייב `npm run build` מחדש,
> ובכל מחשב חדש צריך ליצור את הקובץ מחדש (הוא לא עובר ב-git).

**פעולת חשבון של המשתמש:** לאשר את ה-Cloud Data Processing Addendum של Google
בחשבון Firebase, ולהגביל את ה-API key ואת ה-authorized domains.

## Deploy — אתם מריצים, לא Claude

`firebase deploy` **חסום ל-Claude** (פעולת פרסום). ההכנה כולה מוכנה כאן;
ההרצה היא שלכם:

```bash
npm run build

cmd /c "npx firebase-tools login"
cmd /c "npx firebase-tools deploy --only firestore:rules,storage:rules --project <PROJECT_ID>"
cmd /c "npx firebase-tools deploy --only hosting --project <PROJECT_ID>"
```

(PowerShell חוסם `npx.ps1`, ולכן `cmd /c`.)

`firebase.json` כבר כולל את כותרות ה-cache הנכונות: `index.html` ו-
`manifest.webmanifest` עם `no-cache`, והנכסים עם hash — `immutable`. בלי זה,
טלפון מציג גרסה ישנה אחרי deploy.

### לפני ה-deploy — שני דברים חוסמים

1. **שער עדי (משפטי).** מוצר צרכני ציבורי שאוסף מסמכי זהות: מדיניות פרטיות,
   תנאי שימוש עם הבהרת אמינות בולטת, ו**הצהרת נגישות** — שנדרשת גם אם המחזור
   אפס (הפטור פוטר מהנגשה, לא מההצהרה). **ובנוסף: `npm run emu:rules` ירוק**
   — תנאי סף שאינו ניתן להחלפה בסקירה או בסריקה.
2. ~~**`firebase emulators`**~~ — **בוצע.** (`emu:rules` הוא תנאי סף.) `npm run emu:rules` + `npm run emu:cloud`.
   הנקודה החדה נבדקה ואומתה: **מחיקת אובייקט Storage ללא הרשאת קריאה
   אפשרית** — הבעלים מוחק את סריקת רישיון הנהיגה בלי לראות אותה, ולכן
   ה-cascade עובד ואין קבצים יתומים. התכנון של עדי מחזיק.
