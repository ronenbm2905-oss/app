# `functions/` — שכבת ההובלה של התזכורות (פרוסה 2א)

## 🔴 ההכרעה הארכיטקטונית: למנוע יש מימוש אחד, ואין העתק

**הבעיה.** `functions/` הוא פרויקט npm נפרד עם `package.json` משלו, ו-Firebase
מעלה בפריסה **רק את התיקייה הזאת**. הדרך הטבעית — להעתיק את `reminders.js`
לתוכה — היא בדיוק מה שאסור: ברגע שמישהו ישנה את הסולם `[30,14,7,3,1,0]` בצד
אחד, המוצר ישלח תזכורות בתאריכים שונים ממה שהמסך מבטיח, ואף בדיקה לא תיפול.

**שלוש האפשרויות שנשקלו:**

| גישה | למה נדחתה / נבחרה |
|---|---|
| npm workspaces + חבילת `engine` משותפת | נכונה עקרונית, אבל דורשת להזיז את כל `src/utils/` ולשנות עשרות ייבואים באפליקציה שכבר עברה 633 אסרשנים, e2e ואמולטור. שינוי מבני גדול בשביל בעיה שיש לה פתרון זול יותר. |
| העתקה + בדיקת checksum | "יש העתק, אבל נשמור שהוא זהה". הבדיקה אמנם נופלת בדריפט — אבל היא מתקנת סימפטום. עדיין קיימים שני קבצים שאפשר לערוך. |
| **שלב build שמאגד (esbuild) — נבחר** | **אין העתק בכלל.** `functions/src/` מייבא ישירות מ-`../../src/utils/`, ו-`build.mjs` מאגד הכול ל-`lib/index.js` לפני פריסה. מקור אמת אחד, פיזית. |

**למה זה עומד בקריטריון שננעל** ("שינוי במקום אחד ולא בשני = הבנייה או ה-smoke
נופלים"): הוא עומד בו **חזק יותר** — אין "מקום שני" שאפשר לשנות. ובנוסף,
שלוש בדיקות שומרות שזה יישאר כך:

1. `functions/build.mjs` נכשל אם ייבוא מהמנוע לא נפתר.
2. סריקה סטטית ב-smoke: **אף קובץ ב-`functions/src/` לא מגדיר מחדש** את
   `REMINDER_LADDER`, `computeStatus`, `nextFireDate` או `createReminderLogEntry`.
3. אסרשן זהות בזמן ריצה: הסולם שה-Function מייבאת `===` הסולם ב-`constants.js`.

זהו בדיוק הדפוס של פרויקטי TypeScript ב-Firebase (`tsc` → `lib/`), רק עם
esbuild — ולכן גם `predeploy` וגם `main` מוגדרים בצורה הסטנדרטית.

## מה יש כאן

| קובץ | תפקיד |
|---|---|
| `src/index.js` | נקודת הכניסה — הפונקציות שנפרסות |
| `src/sweep.js` | ★ מנוע הסריקה: מי צריך תזכורת עכשיו, ובאיזה ערוץ |
| `src/providers.js` | ממשק הספקים (`send`) + מימוש מדומה |
| `src/signedUrls.js` | V4 signed URLs — סוגר את N2 ואת PRD §8.4 |
| `src/retention.js` | ניקוי `reminderLog` ומחיקת חשבון בצד השרת |
| `build.mjs` | אגירה ל-`lib/` |

## ⚠️ מה צריך כדי שזה ירוץ באמת

הכול נבנה ונבדק **מול אמולטור בלבד**. כדי להריץ בפרודקשן:

1. **שדרוג ל-Blaze.** תוכנית Spark **אינה מאפשרת Cloud Functions** כלל. זה
   חוסם, ואין לו מעקף.
2. **ספק SMS וספק מייל.** אין ספקים מוגדרים. `src/providers.js` מגדיר ממשק
   צר; חיבור ספק אמיתי הוא **קובץ אחד**. עד אז `deliveryState` יהיה `failed`
   עם `errorCode: "provider-not-configured"` והסולם יסלים הלאה.
3. **FCM.** הצנרת קיימת, אבל טוקני מכשיר אמיתיים דורשים אפליקציה חיה
   (ובפועל — Capacitor, פרוסה 3). ב-Web PWA צריך גם `firebase-messaging-sw.js`.
4. **אינדקס collection-group** על `tasks.schedule.nextFireAt` — קיים ב-
   `firestore.indexes.json` ונפרס עם ה-rules.
