# העלאה לענן — מדריך לרונן

המטרה: שאתה ואנדריי תעבדו על **אותם נתונים**, מכל מחשב, וכל שינוי יופיע אצל
השני בלי לרענן.

⚠ **הפעולות כאן הן שלך ולא שלי.** `firebase deploy` חסום לי בכוונה — פרסום
לאוויר הוא החלטה של בעל העסק. אני מכינה הכול; אתה לוחץ.

⚠ **לפני שמתחילים: הורד גיבוי.** לשונית ״גיבוי״ → ״שמירת גיבוי״. אם משהו
משתבש בדרך, זה מה שמחזיר אותך.

---

## מה יעלה לאוויר

131 כתובות בניינים · 85 ספקים עם טלפונים · 2,715 שורות חוזה עם סכומים ·
3 עובדים · הערות מהגיליון. מידע אמיתי על אנשים אמיתיים — ולכן שלב 5
(פרסום הכללים) הוא לא פורמליות.

## שני מסלולים — בחר אחד

|  | **א. אפס התקנה** ⭐ | **ב. עם Node** |
|---|---|---|
| מה צריך אצלך | דפדפן בלבד | Node.js + הריפו + שורת פקודה |
| האתר | קובץ אחד שאני בונה, אתה גורר לאחסון | `npm run deploy:hosting` |
| הכללים | העתק-הדבק בקונסולה | `npm run deploy:rules` |
| עדכון גרסה | אני שולחת קובץ, אתה גורר שוב | `npm run deploy:hosting` |

**מסלול א׳ הוא מה שאני ממליצה** — זה אותו היגיון שהוביל לקובץ העצמאי.
שלבים 1–3 ו-5 **זהים בשני המסלולים**; רק שלב 6 שונה.

## שלב 1 — פרויקט Firebase

1. [console.firebase.google.com](https://console.firebase.google.com) → **Add project**.
   שם: `vitzman-budget`. Google Analytics — **כבה**, אין בו צורך והוא מוסיף
   מדיניות פרטיות שלא נדרשת.
2. **Firestore Database** → **Create database** →
   - Region: **`me-west1 (Tel Aviv)`** ⚠ **בלתי הפיך.** נקבע פעם אחת ולתמיד.
     בחירה בישראל מוחקת לגמרי את שאלת העברת המידע לחו״ל.
   - Mode: **Production mode** (לא Test mode!)

   ⚠ **Test mode פותח את המסד לכל העולם ל-30 יום.** עם הנתונים האלה זו לא
   אופציה.

3. **Authentication** → **Get started** → **Sign-in method** → הפעל **Google**
   בלבד. אל תפעיל ספקים נוספים.
4. ⚙️ **Project settings** → למטה **Your apps** → אייקון `</>` (Web) →
   שם: `vitzman` → **Register app**.
   ⚠ **אל תסמן** ״Also set up Firebase Hosting״ במסלול א׳.
5. העתק את הבלוק `firebaseConfig` שמופיע.

   ⚠ **הערכים האלה אינם סודות.** הם נשלחים לכל דפדפן שנכנס לאתר — כך Firebase
   בנוי. ההגנה היא הכללים של שלב 5, לא הסתרת המפתח. אפשר להעביר אותם בבטחה.

## שלב 2 — רשימת המורשים

בקונסולה → **Firestore Database** → **Start collection**:

| שדה | ערך |
|---|---|
| Collection ID | `orgs` |
| Document ID | `vitzman` ← **בדיוק כך** |
| Field name | `members` |
| Type | **array** |
| ערכים | `ronenbm2905@gmail.com` · `<המייל של אנדריי>` — שניהם **string**, **באותיות קטנות** |

## שלב 3 — פרסום הכללים ⚠ הקריטי ביותר

**בלי הצעד הזה המסד סגור לחלוטין — האפליקציה לא תקרא כלום.**

קונסולה → **Firestore Database** → לשונית **Rules** → **מחק את כל מה שכתוב שם**
→ הדבק את התוכן המלא של הקובץ `firestore.rules` (אני אשלח לך אותו כטקסט
מוכן להדבקה) → **Publish**.

אחרי הפרסום ודא שאתה רואה שם `orgs/{orgId}` ו-`members`, ולא
`allow read, write: if false`.

## שלב 5 — העלאת האתר

### מסלול א׳ — אפס התקנה

1. [app.netlify.com/drop](https://app.netlify.com/drop) (או כל אחסון סטטי).
2. שים את הקובץ ששלחתי בתיקייה **ריקה** בשם `vitzman-site`, ו**גרור את
   התיקייה** לחלון. הקובץ חייב להיקרא `index.html`.
3. תקבל כתובת כמו `https://random-name-123.netlify.app`.
4. ⚠ **חובה:** קונסולת Firebase → **Authentication** → **Settings** →
   **Authorized domains** → **Add domain** → הדבק את הדומיין (בלי `https://`).

   **בלי הצעד הזה ההתחברות תיכשל** — Google מסרב לפתוח חלון התחברות לדומיין
   שאינו מורשה.

### מסלול ב׳ — עם Node

```
npm install
npm run build
npx firebase-tools login
npx firebase-tools deploy --only firestore:rules,hosting
```

בחלון `cmd` ולא PowerShell (הוא חוסם `npx.ps1`). ⚠ **פרסם כללים ואתר יחד** —
פרסום hosting לבדו משאיר כללים ישנים בתוקף.

## שלב 6 — העברת הנתונים

1. פתח את הכתובת → **התחברות עם Google** בחשבון שברשימה.
2. אם באותו דפדפן כבר עבדת מקומית, יופיע כפתור
   **״העלאת הנתונים המקומיים לענן״** — לחץ עליו.

   ⚠ **אל תגרור את האקסל מחדש** אם כבר עשית עריכות. ייבוא חוזר מחליף הכול
   ומוחק כל שינוי שעשית מאז — מחירים, שיוכים, מנהלי איזור, ביקורות. הכפתור
   מעלה את מה שיש לך **כולל** העריכות.

3. אם אתה על מחשב אחר: לשונית ״גיבוי״ → ״טעינת גיבוי״ עם הקובץ ששמרת.
4. ודא שהדשבורד מראה **1,088,983 / 940,050 / 148,933**. אם כן — הכול עבר.

## שלב 7 — ⚠ אימות בפועל שההגנה עובדת

**כלל שלא נבדק הוא כלל שלא ידוע אם הוא עובד.** בדקתי 26 תרחישים מול אמולטור,
אבל הפרויקט שלך אינו האמולטור.

חלון **גלישה בסתר** → אותה כתובת → התחבר עם **חשבון Google שאינו ברשימה**.
**התוצאה הנכונה:** מסך ״החשבון אינו ברשימת המורשים״.
**אם ראית נתונים — עצור מיד והודע לי.**

## שלב 8 — הוספת אנדריי

לשונית **״ניהול״** → ״גישה למערכת״ → הוסף את הכתובת שלו → הוא נכנס לאותה
כתובת ומתחבר. אין הזמנה במייל ואין סיסמה.

⚠ **תקרה של 3 מורשים** — קו משפטי, לא טכני. מאגר בבעלות יחיד עם עד שני בעלי
הרשאה נוספים נהנה מהחובות המצומצמות ביותר בתקנות אבטחת מידע (רונן אישר
3.9.2026 שהחברה בבעלות יחיד, ולכן הקטגוריה חלה). מורשה רביעי מחייב נוהל
אבטחה כתוב, תיעוד גישה, הדרכות וביקורת אחת ל-24 חודשים. המערכת תחסום עד אז.

## הסרת גישה — ⚠ אינה זהה למחיקת עובד

**מחיקת עובד מרשימת העובדים אינה מסירה את גישתו.** שתי רשימות נפרדות:
עובדים = מי אחראי על בניינים; מורשים = מי יכול להיכנס.

כשמישהו עוזב: **״ניהול״ → ״גישה למערכת״ → הסרה.** נכנס לתוקף מיד, בלי deploy.
אתה לא יכול להסיר את עצמך — זה היה נועל את כולם החוצה.

## מה עולה כסף

התוכנית החינמית (Spark) מספיקה: 50,000 קריאות ו-20,000 כתיבות ליום.
טעינה מלאה היא ~3,300 קריאות, אבל **רק בפעם הראשונה** — יש מטמון מקומי
מתמיד, ואחריו מגיעים רק ההפרשים. שני משתמשים לא מתקרבים לתקרה.

## אם משהו נשבר

| תסמין | הסיבה כמעט תמיד |
|---|---|
| ״טעינת הנתונים נכשלה״ | הכללים לא פורסמו (שלב 3), או שהמייל לא ב-`members` |

| ״אינו ברשימת המורשים״ למרות שהוספת | התחברת עם חשבון Google אחר — בדוק איזה מייל מוצג במסך |
| התג נשאר ״מקומי״ | זה הקובץ העצמאי ולא קובץ הענן. הם שני קבצים שונים |
| הכול נעלם | פרויקט Firebase אחר = מסד אחר |

⚠ **קובץ ענן אינו מתעדכן מעצמו.** גרסה חדשה = אני בונה, אתה גורר שוב.
