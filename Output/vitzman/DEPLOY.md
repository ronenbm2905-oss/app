# העלאה לענן — מדריך לרונן

המטרה: שאתה ואנדריי תעבדו על **אותם נתונים**, מכל מחשב, וכל שינוי יופיע אצל
השני בלי לרענן.

⚠ **הפעולות כאן הן שלך ולא שלי.** `firebase deploy` חסום לי בכוונה — פרסום
לאוויר הוא החלטה של בעל העסק. אני מכינה הכול; אתה מריץ שלוש פקודות.

⚠ **לפני שמתחילים: הורד גיבוי.** לשונית ״גיבוי״ → ״שמירת גיבוי״. אם משהו
משתבש בדרך, זה מה שמחזיר אותך.

---

## מה יעלה לאוויר

131 כתובות בניינים · 85 ספקים עם טלפונים · 2,715 שורות חוזה עם סכומים ·
3 עובדים · הערות מהגיליון. זה מידע אמיתי על אנשים אמיתיים, ולכן יש כאן
שלב אבטחה שאסור לדלג עליו (שלב 5).

## שלב 1 — פרויקט Firebase

1. [console.firebase.google.com](https://console.firebase.google.com) → **Add project**.
   שם: `vitzman-budget` (או מה שתרצה). Google Analytics — אפשר לכבות.
2. **Firestore Database** → **Create database** → בחר **Production mode**
   (לא Test mode!) → region: **`me-west1`** (תל אביב) או `europe-west1`.

   ⚠ **Test mode פותח את המסד לכל העולם ל-30 יום.** עם הנתונים האלה זה לא
   אופציה. אם בטעות בחרת Test mode — שלב 5 סוגר את זה, אבל אל תשאיר את זה פתוח.

3. **Authentication** → **Get started** → **Sign-in method** → הפעל **Google**.
4. ⚙️ **Project settings** → למטה **Your apps** → אייקון `</>` (Web) →
   שם: `vitzman` → **Register app** → העתק את הבלוק `firebaseConfig`.

## שלב 2 — קובץ `.env`

בתיקיית `Output/vitzman/`, צור קובץ בשם `.env` (בדיוק כך, בלי סיומת) והדבק:

```
VITE_FIREBASE_API_KEY=<apiKey מהקונסולה>
VITE_FIREBASE_AUTH_DOMAIN=<authDomain>
VITE_FIREBASE_PROJECT_ID=<projectId>
VITE_FIREBASE_STORAGE_BUCKET=<storageBucket>
VITE_FIREBASE_MESSAGING_SENDER_ID=<messagingSenderId>
VITE_FIREBASE_APP_ID=<appId>
VITE_ORG_ID=vitzman
```

ואז ב-`.firebaserc` החלף את `REPLACE_WITH_PROJECT_ID` ב-`projectId` שלך.

⚠ המפתחות האלה **פומביים במהותם** — הם נשלחים לכל דפדפן שנכנס. זו לא תקלה:
ההגנה האמיתית היא הכללים של שלב 5, לא הסתרת המפתח.

## שלב 3 — רשימת המורשים

בקונסולה → **Firestore Database** → **Start collection**:

- Collection ID: `orgs`
- Document ID: `vitzman` ← **בדיוק כמו `VITE_ORG_ID`**
- Field: `members` · type **array** · שני ערכים (string):
  `ronenbm2905@gmail.com` ו-`<המייל של אנדריי>`

⚠ **באותיות קטנות.** המערכת ממירה לאותיות קטנות בשני הצדדים, אבל עדיף
שיהיה נכון מלכתחילה.

## שלב 4 — התקנה ובנייה

```
npm install
npm run build
```

## שלב 5 — פרסום הכללים ⚠ הכי חשוב

**בלי הצעד הזה המסד או סגור לחלוטין או פתוח לחלוטין.** אין אמצע.

בחלון `cmd` (לא PowerShell — הוא חוסם `npx.ps1`), בתיקיית `Output/vitzman/`:

```
npx firebase-tools login
npx firebase-tools deploy --only firestore:rules
```

בקונסולה → Firestore → **Rules** — ודא שאתה רואה את `orgs/{orgId}` ואת
`members`, ולא `allow read, write: if false`.

## שלב 6 — העלאת האתר

⚠ **פרסם כללים ואתר יחד.** פרסום hosting לבדו משאיר כללים ישנים בתוקף —
עדכנת את `firestore.rules` ושכחת? האתר החדש רץ מול ההגנה הישנה.

```
npx firebase-tools deploy --only firestore:rules,hosting
```

בסוף תקבל כתובת כמו `https://vitzman-budget.web.app`. זו הכתובת שאתה
ואנדריי פותחים — מכל מחשב, מכל דפדפן.

## שלב 7 — העברת הנתונים

1. פתח את הכתובת → **התחברות עם Google** בחשבון שברשימה.
2. אם באותו דפדפן כבר עבדת מקומית, יופיע כפתור
   **״העלאת הנתונים המקומיים לענן״** — לחץ עליו.

   ⚠ **אל תגרור את האקסל מחדש** אם כבר עשית עריכות. ייבוא חוזר מחליף הכול
   ומוחק כל שינוי שעשית מאז — מחירים, שיוכים, ביקורות. הכפתור מעלה את מה
   שיש לך **כולל** העריכות.

3. אם אתה על מחשב אחר: לשונית ״גיבוי״ → ״טעינת גיבוי״ עם הקובץ ששמרת.
4. ודא שהדשבורד מראה **1,088,983 / 940,050 / 148,933**. אם כן — הכול עבר.

## שלב 7ב — ⚠ אימות בפועל שההגנה עובדת

**כלל שלא נבדק הוא כלל שלא ידוע אם הוא עובד.** בדקתי 26 תרחישים מול אמולטור,
אבל הפרויקט שלך הוא לא האמולטור.

פתח **חלון גלישה בסתר** → אותה כתובת → התחבר עם **חשבון Google שאינו ברשימה**
(חשבון פרטי, של בן משפחה, כל דבר). **התוצאה הנכונה:** מסך ״החשבון אינו ברשימת
המורשים״. אם ראית נתונים — **עצור והודע לי מיד.**

## שלב 8 — הוספת אנדריי

לשונית **״ניהול״** → ״גישה למערכת״ → הוסף את הכתובת שלו → הוא נכנס לאותה
כתובת אתר ומתחבר. אין הזמנה במייל ואין סיסמה.

⚠ **תקרה של 3 מורשים.** זו אינה מגבלה טכנית אלא קו משפטי: מאגר בניהול יחיד
עם עד שני בעלי הרשאה נוספים נהנה מהחובות המצומצמות ביותר בתקנות אבטחת מידע.
מורשה רביעי מחייב נוהל אבטחה כתוב, תיעוד גישה, הדרכות וביקורת תקופתית. אם
באמת צריך רביעי — זו שיחה עם עורך דין. המערכת תחסום אותך עד אז.

## הסרת גישה — ⚠ אינה זהה למחיקת עובד

**מחיקת עובד מרשימת העובדים אינה מסירה את גישתו למערכת.** אלה שני דברים
נפרדים: רשימת העובדים היא מי אחראי על בניינים; רשימת המורשים היא מי יכול
להיכנס.

כשמישהו עוזב: **״ניהול״ → ״גישה למערכת״ → הסרה.** ההסרה נכנסת לתוקף מיד,
בלי deploy. אתה לא יכול להסיר את עצמך — זה היה נועל את כולם החוצה.

## מה עולה כסף

התוכנית החינמית (Spark) מספיקה: 50,000 קריאות ו-20,000 כתיבות ליום.
טעינה מלאה היא ~3,300 קריאות, אבל **רק בפעם הראשונה** — יש מטמון מקומי
מתמיד, ואחריו מגיעים רק ההפרשים. שני משתמשים לא מתקרבים לתקרה.

## אם משהו נשבר

| תסמין | הסיבה כמעט תמיד |
|---|---|
| ״טעינת הנתונים נכשלה״ | הכללים לא פורסמו (שלב 5) או שהמייל לא ב-`members` |
| נכנס ורואה מסך ייבוא ריק | `orgs/vitzman` לא קיים, או ש-`VITE_ORG_ID` לא תואם למזהה המסמך |
| ״אינו ברשימת המורשים״ למרות שהוספת | התחברת עם חשבון Google אחר — בדוק איזה מייל מופיע במסך |
| התג נשאר ״מקומי״ | `.env` לא נקרא — הוא נקרא **בזמן `npm run build`**, אז בנה מחדש |
| הכול נעלם אחרי שינוי config | פרויקט Firebase אחר = מסד אחר. בדוק `projectId` |

**כל שינוי ב-`.env` דורש `npm run build` מחדש** — הערכים מוטמעים בקוד בזמן
הבנייה, לא נקראים בזמן ריצה.

## הקובץ העצמאי ממשיך לעבוד

`vitzman.html` שיש לך נשאר כמו שהוא — מקומי, בלי ענן, בלי התחברות. הוא
נבנה בלי Firebase בכלל (640KB במקום 1.1MB). שימושי לעבודה במקום בלי
אינטרנט, אבל **הוא לא מסתנכרן** — מה שתעשה בו לא יגיע לענן.
