# הקמת הענן — מה שרק אתה יכול לעשות

הקוד מוכן. השלבים כאן דורשים את חשבון ה-Google שלך ולכן חסומים בפניי.
עד שהם יושלמו, האפליקציה ממשיכה לרוץ **במצב מקומי** בדיוק כמו היום.

> ⚠ **לפני שנתונים אמיתיים עולים לענן** — נדרשת סקירה משפטית (שער עדי).
> חשבוניות של ספקים הן מידע עסקי של **צד שלישי**, והעלאתן לשרת חיצוני עם
> שיתוף לשני אנשים נוספים היא בדיוק סוג ההחלטה שהשער נועד לה. אפשר להקים
> הכול ולבדוק עם נתוני דמו לפני כן.

---

## 1. יצירת פרויקט Firebase 👤

1. https://console.firebase.google.com → **Add project**
2. שם: `pinsker-budget` (או מה שתבחר). אפשר לכבות Analytics.
3. אחרי היצירה — **Project settings → General → Your apps → Web (`</>`)**
   רשום אפליקציה בשם `project-budget`, והעתק את אובייקט ה-config.

## 2. הפעלת השירותים 👤

בקונסולה של הפרויקט:

- **Build → Firestore Database → Create database**
  - מצב: **Production mode** (הכללים שלנו יידרסו עליו בשלב 4)
  - מיקום: **`me-west1`** (ישראל) — לא ניתן לשינוי אחר כך.
- **Build → Authentication → Get started → Sign-in method → Google → Enable**
  - הוסף את המייל שלך כ-**Authorized domain** אם נדרש.
- **Build → Storage → Get started** (לקבצי החשבוניות), אותו מיקום.

> Storage דורש תוכנית **Blaze** (חיוב לפי שימוש). בהיקף של פרויקט אחד העלות
> זניחה, אבל זו החלטה שלך. בלי Storage הכול עובד — רק העלאת קבצים לא.

## 3. מילוי `.env` 👤

```bash
cp .env.example .env
```

ומלא מתוך ה-config שהעתקת בשלב 1:

```
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=...
VITE_FIREBASE_PROJECT_ID=...
VITE_FIREBASE_STORAGE_BUCKET=...
VITE_FIREBASE_MESSAGING_SENDER_ID=...
VITE_FIREBASE_APP_ID=...
```

**ברגע שהקובץ קיים האפליקציה עוברת למצב ענן** ותדרוש התחברות.

> ⚠ **גבה לפני המעבר.** הנתונים שבמצב המקומי יושבים ב-localStorage ולא עוברים
> לענן לבד. לחץ "גיבוי" בפס העליון, ואחרי ההתחברות — "שחזור" על אותו קובץ.

## 4. פריסת הכללים 👤

```bash
firebase login
firebase use --add
```

בחר את הפרויקט שיצרת ותן לו alias `default`. אחר כך:

```bash
firebase deploy --only firestore:rules,storage
```

> `firebase deploy` חסום בפניי — הרץ ידנית.

## 5. בדיקה

```bash
npm run build
npm run preview
```

התחבר עם Google, צור פרויקט, ואמת שאתה מקבל תפקיד **בעלים**.
אחר כך בלשונית **הרשאות** הוסף את חברת הניהול (`manager`) ואת אריאל (`viewer`).

---

## מה כבר נבדק — ומה לא

| | |
|---|---|
| ✅ `firestore.rules` | **35 בדיקות מול האמולטור האמיתי** (`npm run test:rules`) — קריאה, שאילתות, הפרדת תפקידים, ניהול חברים |
| ✅ מודל התפקידים בקוד | 17 בדיקות ב-`npm run smoke` |
| ⚠ `storage.rules` | נכתבו ונבדקו בקריאה, **לא הורצו** — אמולטור Storage לא הופעל כאן |
| ⚠ מסלול הענן בקליינט | `subscribeProject` / `writeProjectDiff` / התחברות Google — **לא רצו מול פרויקט אמיתי** |

השורה השנייה־מלמטה חשובה: הכללים בדוקים היטב, אבל **חיווט הקליינט לענן טרם
רץ ולו פעם אחת מול Firebase חי.** צפה לתקלות קטנות בסבב הראשון, ותעדכן אותי.

---

## מונחים בקצרה

- **חשבונית נכנסת רק דרך המייל.** אין הזמנות ואין אישור — הבעלים מוסיף כתובת
  בלשונית "הרשאות", ומי שנכנס עם אותה כתובת ל-Google מקבל את התפקיד.
- **הבעלים האחרון לא ניתן להסרה** — נאכף גם בממשק וגם בכללים.
- **חברת הניהול לא נוגעת בדרישה מהרשות.** היא מזינה חשבוניות, תשלומים וספקים;
  שיוך למנה, סטטוס ההגשה והסכום שאושר שמורים לבעלים.
